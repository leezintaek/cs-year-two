프로시저, 재사용 가능한 코드 블록이라고 생각하자. 
여기서 가장 주요하게 알아야 할 것은 %rip, %rsp 이다. 전자는 다음 수행해야 할 코드를 뜻하며, 후자는 뒤에 나올 스택의 top 주소이다.
왜 프로시저를 쓰는가? 아까 말했듯이 프로시저는 재사용 가능한 코드 블록이다. 또한, 호환성을 높여주는 도구라 생각하면 된다. 우리가 어떤 함수를 100번 사용해야 할 때 만약 프로시저를 이용하지 않는다면, 그 함수 자체를 100번 적어야 하며 이는 비효율적일 것이다.
여기서 ABI를 알고 가보자. ISA는 앞 챕터에 나오듯이 하드웨어가 소프트웨어에게 주는 도구라 생각하면 된다. ABI는 ISA를 기반으로 바이너리 수준에서 어떻게 사용할 것인지를 규약한 것이다.
같은 ISA를 쓰더라도 ABI가 다를 수 있다. 여기서는 리눅스 x86-64 를 기반으로 하기에 AMD V 64를 기반으로 설명한다.
ABI는 gABI와 psABI로 나뉜다. 여기서 gABI는 프로세서에 독립적이며 psABI는 프로세서에 의존적이다. 이는 gABI는 os, kernel 등이 해당하고, psABI는 스택사용법 등 프로세서가 중요한 것들이 해당한다.
ABI는 크게 4가지 Calling Convention으로 나뉠수 있다. Stack Operaton, Calling data, Calling control, Register saving convention이 해당한다.
Stack Operation부터 보자. High Level에서 함수를 부를때 binary 수준에서는 call 을 통해 이동한다. 이것을 위해서는 함수가 끝났을 때 돌아올 주소 즉 return address를 알고 있어야 한다. 그래서 ABI는 이 주소를 스택에 저장한다.
스택에 저장하는 방식은 위로 쌓는게 아닌 아래로 쌓는 FIFO 형식이다. 스택의 top에는 %rsp가 주소를 가리키고 있는데 이 %rsp를 -8바이트 하고(주소의 크기) 여기에 return adress를 저장한다. 그리고 함수가 끝났을 때는 stack top 즉 %rsp 값을 가져오고 %rsp에 8을 더한다.
Passing control을 보자. call은 복귀 주소를 스택에 저장하고, ret에서는 스택 값을 pop하며 돌아온다.
call 한번에 하나의 스택 프레임이 동적으로 생성되는데, 이 스택 프레임은 가변적이다. 왜냐하면 스택 프레임은 최소 크기를 지향한다. 그렇기에 일단 call을 하면 스택 프레임에는 복귀 주소만 저장하고, 필요 할 경우에만 추가로 할당한다.
이때, 필요한 경우는 언제일까? 함수에서 지역 변수는 보통 남는 6개의 범용 레지스터에 저장하는데, 이보다 더 많은 변수를 저장하는 경우이다. 그리고 포인터로 값을 인자를 사용하는 경우나 배열의 경우 스택에 저장한다. 또한 레지스터에 값을 저장하고 인자로 전달할때,
callee에서 이 레지스터 값이 오염될 수가 있다. 이를 지양하기 위해 사용된다.
Passing data를 보자. 보통 인자는 레지스터에 저장한다. 하지만 6개가 넘는 값을 저장하면, 더이상 저장할 공간이 없기에 스택에 저장하는 경우가 있다. 이때 %rsp값을 컴파일러 임의적으로 옮기지 않고 저장하며 사용하는 경우도 생긴다.
Register saving convention은 아까 말했듯이 인자로 값을 전달 할 때 레지스터 값이 오염될 수 있는 가능성이 있는 경우 사용한다. 스택에 caller에서 값을 저장하고 리턴 값을 넣고 return adree를 pop하고 나서 원래 레지스터에 mov를 하는 식으로 사용한다
