# 중간고사 모의문제 Q&A

## [Set 1 - 20번] `tmult_ok`의 캐스팅 위치

**Q.** `x * y`를 곱하기 전에 x와 y를 각각 64비트로 만든 뒤 곱해야 32비트 오버플로우가 안 나는 것 아닌가?

**A.** 맞다. 정답 `(int64_t) x * y`가 바로 그렇게 동작한다.

### 1. `(int64_t) x * y`는 둘 다 64비트로 만들어 곱한다

- 캐스트 연산자 `(int64_t)`는 `*`보다 우선순위가 높다. 그래서 `((int64_t) x) * y`로 해석된다.
- 그러면 `int64_t * int`가 된다. C의 usual arithmetic conversion 규칙에 따라 작은 쪽인 `y`도 자동으로 `int64_t`로 변환된다.
- 결과적으로 `(int64_t) x * (int64_t) y`와 완전히 같다. 둘 중 하나만 캐스팅해도 되고, 둘 다 캐스팅해도 정답이다.

### 2. 64비트에서는 곱셈이 절대 오버플로우되지 않는다

- int 범위는 −2³¹ ~ 2³¹−1이다.
- 곱의 절댓값이 가장 큰 경우는 (−2³¹) × (−2³¹) = 2⁶²이다.
- int64_t 최댓값은 2⁶³−1이므로 어떤 int 두 개를 곱해도 결과가 정확하게 들어간다.
- 강의 내용 그대로: w비트 두 수의 곱은 최대 2w비트가 필요하다.

### 3. `pll == (int) pll`로 오버플로우를 판단한다

- `(int) pll`: 하위 32비트만 남긴다(truncation).
- 비교할 때 이 값은 다시 64비트로 sign-extend 된다.
- 정확한 곱이 int 범위 안이면 잘라도 값이 그대로라서 같다 → 1 반환.
- 범위를 벗어나면 상위 비트가 사라져서 값이 달라진다 → 0 반환.

### 4. 틀린 버전과 비교 (x = y = 50000)

정확한 곱은 2,500,000,000으로, INT_MAX(2,147,483,647)를 넘는다.

**맞는 코드** `int64_t pll = (int64_t) x * y;`
- pll = 2,500,000,000 (64비트에서 정확하게 계산됨)
- `(int) pll` = 2,500,000,000 − 2³² = −1,794,967,296
- 두 값이 다르므로 0 반환 → 오버플로우를 제대로 잡는다.

**틀린 코드** `int64_t pll = x * y;` 또는 `(int64_t)(x * y)`
- 곱셈이 int(32비트)에서 먼저 일어나 이미 −1,794,967,296으로 wrap 된다.
- 그 결과를 64비트로 sign-extend 해도 pll = −1,794,967,296이다.
- `(int) pll`도 −1,794,967,296이라 같으므로 1 반환 → 오버플로우를 놓친다.

### 5. 어셈블리로 보면

```
# 맞는 코드: 먼저 64비트로 확장한 뒤 64비트 곱셈
movslq %edi, %rax      # x → 64비트 sign-extend
movslq %esi, %rsi      # y → 64비트 sign-extend
imul   %rsi, %rax      # 64비트 곱셈 (imulq)

# 틀린 코드: 32비트 곱셈 후 확장
imul   %esi, %edi      # 32비트 곱셈 (imull) → 여기서 이미 오버플로우
movslq %edi, %rax      # 잘못된 결과를 확장
```

핵심: **확장(캐스팅)이 곱셈보다 먼저 일어나야 한다.** 괄호 위치 하나로 결과가 달라진다.
