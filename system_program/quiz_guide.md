# 시스템프로그래밍 퀴즈 출제 가이드

퀴즈를 새로 만들 때마다 이 파일을 먼저 읽고 따른다.
기준 형식: `midterm_quiz/quiz_set1~5.md`

## 출제 범위

- 사용자가 말한 범위만 출제한다.
- 범위를 말하지 않았으면 **출제 전에 먼저 물어본다.**
- 참고 자료: `final_sum/`, `week*/lecture_summary.md`, 강의 PDF
- `ownSum/`은 참고하지 않는다.

## 문제 구성

- 기본 20문항: T/F 5 · 객관식 6 · 단답형 5 · 빈칸 손코딩 4
- 언어: C / x86-64 AT&T 어셈블리
- 문항 번호는 `**N.**`로 Part와 상관없이 1번부터 이어서 매긴다.

| Part | 제목                     | 형식                              |
|------|--------------------------|-----------------------------------|
| A    | `T/F (O/X)`              | 한 문장 진술                      |
| B    | `객관식`                 | 보기 ①~④ 한 줄                    |
| C    | `단답형`                 | 소문항 (a)(b)…, 계산·해석         |
| D    | `빈칸 채우기 손코딩`     | C·어셈블리 코드에 `____(a)____`   |

## 파일 형식

파일 맨 위 헤더는 아래 형식을 따른다.

```
# 기말고사 대비 모의문제 — Set N

> 범위: <사용자가 지정한 범위>
> 구성: T/F 5 · 객관식 6 · 단답형 5 · 빈칸 손코딩 4 (C / x86-64 AT&T 어셈블리)
> 환경 가정: x86-64 Linux, gcc `-Og`, `-fwrapv`, `-fcf-protection=none`, little endian, w = 32 (int)
> 인자 `%rdi, %rsi, %rdx, %rcx, %r8, %r9` / 반환값 `%rax`
> 정답과 해설은 맨 아래에 있다.
```

- Part 사이는 `---`로 나눈다.
- 문제가 끝나면 `---`를 두 줄 쓰고 `## 정답 및 해설`을 둔다.

## 정답·해설

- 정답과 해설은 **문제 파일 맨 아래**에 함께 쓴다 (별도 정답 파일 없음).
- 정답은 굵게 쓰고 `—` 뒤에 짧은 근거를 붙인다. 예: `**4. X** — lea는 플래그를 건드리지 않는다.`
- 계산 문제는 중간 과정을 줄 단위로 보여 준다.
- 객관식은 매력적인 오답 보기가 왜 틀렸는지도 쓴다 (예: Set 1 7번의 1의 보수, sign-magnitude 보기).
- 어셈블리·C 출력 문제는 가능하면 직접 컴파일·실행해서 정답을 확인한다.

## 문제 스타일

- 개념을 그대로 묻기보다 **함정 포인트**를 노린다.
  - 예: `lea`는 플래그 불변·메모리 안 읽음, 32비트 연산은 상위 32비트를 0으로, 캐스팅 위치, 산술 시프트는 내림
- 빈칸 손코딩은 강의 예제를 살짝 바꾸고, 강의 코드의 허점이 있으면 그것을 노린다 (예: Set 1 17번 `sum >= 0`).
- `족보/족보_분석.md`의 반복 유형이 범위에 들어가면 포함한다.
  - 메모리 표 + mov/lea/movs, jmp 보고 C 빈칸 채우기, cmp 직후 플래그, 컴파일 단계 등
- 이전 세트와 문제가 겹치지 않게 한다.
- 표는 CLAUDE.md 규칙대로 세로선을 맞춘다.

## 질문·기록

- 사용자가 물어본 문제의 해설은 **채팅으로만** 답한다.
- 질문이나 해설을 따로 파일로 만들거나 기록하지 않는다. 필요하면 사용자가 직접 요청한다.
