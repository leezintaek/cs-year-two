## 족보1

### 1번. static 지역/전역 변수 출력 순서 ✅ (1) / ❌ (2)

```c
static int x = 21;   //A
void useLocal()       { int x = 10;         printf x; x++; printf x; }   // [01] [02]
void useStaticLocal() { static int x = 100; printf x; x++; printf x; }   // [03] [04]
void useGlobal()      {                     printf x; x--; printf x; }   // [05] [06]
int main() {
    int x = 3;  [07]
    { int x = 4; [08] }
    [09]
    useLocal(); useStaticLocal(); useGlobal();
    useLocal(); useStaticLocal(); useGlobal();
    [10]
}
```

**(1) 정답**
```
[07] 3     [08] 4     [09] 3
[01] 10    [02] 11    [03] 100   [04] 101   [05] 21   [06] 20
[01] 10    [02] 11    [03] 101   [04] 102   [05] 20   [06] 19
[10] 3
```

- `[08]`: 안쪽 블록의 `x = 4`가 바깥 `x`를 가린다. 블록을 나가면 `[09]`는 다시 3이다.
- `useLocal`: 일반 지역 변수라 호출할 때마다 10으로 새로 초기화된다. 두 번 다 10 → 11.
- `useStaticLocal`: static 지역 변수는 **초기화가 한 번만** 되고 값이 유지된다. 100 → 101, 그다음 호출은 101 → 102.
- `useGlobal`: 함수 안에 `x` 선언이 없으므로 전역 `x`(21)를 쓴다. 21 → 20, 그다음 20 → 19.
- `[10]`: main의 지역 `x`는 아무도 건드리지 않았으므로 3이다.

**(2) A와 B의 static 차이**
- 족보 답 "A는 다른 모듈(파일)에서도 사용할 수 있다" → ❌ **반대**다.
- **A (전역 static)**: 이 변수를 **현재 파일 안에서만** 볼 수 있게 제한한다(internal linkage). 다른 파일에서 `extern`으로 접근할 수 없다.
- **B (지역 static)**: 이 변수를 **스택이 아닌 데이터 영역**에 두어 함수가 끝나도 값이 유지된다. 초기화는 처음 한 번만 한다. 보이는 범위는 함수 안이다.

> 모범 답안: A는 전역 변수의 범위를 해당 파일로 제한하고, B는 지역 변수의 수명을 프로그램 전체로 늘려 호출 사이에 값을 유지한다.

### 2번. 정수 오버플로우 출력

**(1)** `char a = 100, b = 30; char c = a + b;` → 족보 답 130 ❌ → 정답 **−126**
- `a + b`는 int로 계산되어 130이다. 이 값을 `char`(8비트 signed, −128 ~ 127)에 넣으면 하위 8비트만 남는다.
- 130 = `1000 0010`(2) → signed 8비트로 해석하면 130 − 256 = **−126**

**(2)** `int x = INT_MIN; printf("%d", 2*x);` → **0** ✅
- `INT_MIN` = `0x80000000`. 2를 곱하는 것은 왼쪽 1비트 시프트와 같다 → `0x1_0000_0000`
- 32비트로 잘리면 `0x00000000` = **0**

### 3번. 어셈블리 → C (`arith`)

```
lea  (%rsi,%rsi,4), %rax      # rax = y + 4y = 5y
sub  %rax, %rdx               # rdx = z - rax
mov  %rdx, (%rdi,%rsi,8)      # *(x + 8*y) = rdx  →  x[y] = rdx
retq
```
인자 순서: `x` = `%rdi`, `y` = `%rsi`, `z` = `%rdx`

**(1) 정답**
```c
void arith(long x[], long y, long z)
{
    long t1 = 5*y;       // (또는 y*5, y + 4*y)
    long t2 = z - t1;
    x[y] = t2;
}
```
- 족보 답 `t2 = -t1` ❌: `sub %rax, %rdx`는 **`rdx = rdx − rax`**(AT&T 문법은 *dest = dest − src*)이므로 `z - t1`이다.
- 족보 답 `x[z] = t2` ❌: 인덱스 레지스터가 `%rsi`(= y)이고 scale 8은 `long`의 크기이다 → `x[y]`.

**(2) gdb 명령** → 족보 답 `objdump -d` ❌ → 정답 **`disas arith`** (또는 `disassemble arith`)
- `objdump -d`는 셸에서 쓰는 별도 프로그램이지 gdb 명령이 아니다.
- 출력 첫 줄이 "Dump of assembler code for function arith:"인 것이 gdb `disas`의 형식이다.

### 4번. 컴파일 시스템 4단계 ✅

| 단계   | 프로그램        | 입력 → 출력     | 하는 일                             |
|--------|-----------------|-----------------|-------------------------------------|
| 전처리 | 전처리기 `cpp`  | `.c` → `.i`     | `#include`, `#define` 처리          |
| 컴파일 | 컴파일러 `cc1`  | `.i` → `.s`     | C를 어셈블리 텍스트로 변환          |
| 어셈블 | 어셈블러 `as`   | `.s` → `.o`     | 기계어 오브젝트(재배치 가능) 생성   |
| 링크   | 링커 `ld`       | `.o` → 실행파일 | 다른 `.o`, 라이브러리와 결합        |

족보 답은 내용이 맞다. 프로그램 이름(`cpp`, `cc1`, `as`, `ld`)까지 쓰면 더 확실하다.

### 5번. 메모리 표 + lea / mov / movs

```
Address  +0 +1 +2 +3 +4 +5 +6 +7
0x30     51 32 43 7A 3B FA E4 76
0x38     48 22 00 88 9A B2 CD 27
0x40     4F 17 B3 2B A0 A7 BC F9
0x48     40 03 08 15 A9 8B F2 3F
0x50     AA BB CC DD EE FB 01 02
%rax = 0x40,  %rsi = 0x2
```

**(a)** `leaq (%rsi,%rsi,4), %rbx` → **`0x0000 0000 0000 000A`** ✅
- lea는 메모리를 읽지 않고 주소 계산 결과만 넣는다: 2 + 2×4 = 10 = 0xA

**(b)** `movw 10(%rax), %cx` → 족보 답 `0x0803` ❌ → 정답 **`0x1508`**
- 주소 = 0x40 + 10 = 0x40 + **0xA** = **0x4A** (10을 16진수 0x10으로 읽으면 안 된다)
- 2바이트 읽기: 0x4A = `08`, 0x4B = `15`
- little endian이므로 높은 주소 바이트가 상위 → **`0x1508`**

**(c)** `movsbl -2(%rax,%rsi,2), %edi` → 족보 답 `0x0000 0017` ❌ → 정답 **`0xFFFFFFB3`**
- 주소 = 0x40 + 2×2 − 2 = **0x42**
- 1바이트 읽기: 0x42 = `B3` = `1011 0011` → MSB가 1
- `movsbl`은 byte → long(32비트) **부호 확장** → 상위 24비트를 1로 채움 → **`0xFFFFFFB3`**

### 6번. INT_MIN과 signed/unsigned 비교 → 족보 답 `2 3 4 5` ❌ → 정답 **`2 3`**

```c
int x = INT_MIN;                 // 0x80000000
unsigned int y = (unsigned int)x; // 0x80000000 = 2147483648
int z = ~x;                       // 0x7FFFFFFF = INT_MAX
```

| 조건          | 비교 방식 | 실제 값                        | 결과 |
|---------------|-----------|--------------------------------|------|
| `-1 < 0U`     | unsigned  | `0xFFFFFFFF < 0`               | 거짓 |
| `-x < 0`      | signed    | `-INT_MIN = INT_MIN < 0`       | 참   |
| `x-1 < y`     | unsigned  | `0x7FFFFFFF < 0x80000000`      | 참   |
| `y <= z`      | unsigned  | `0x80000000 <= 0x7FFFFFFF`     | 거짓 |
| `x + z <= 0U` | unsigned  | `-1` → `0xFFFFFFFF <= 0`       | 거짓 |

- 한쪽이라도 unsigned면 **둘 다 unsigned로 바꿔서** 비교한다.
- `-INT_MIN`은 표현할 수 없어서 다시 `INT_MIN`이 된다 (`-fwrapv` 기준).
- `x - 1` = `0x7FFFFFFF`(INT_MAX)로 넘어간다.
- `x + z` = `0x80000000 + 0x7FFFFFFF` = `0xFFFFFFFF` = −1
- 실행해서 출력 `2 3`을 확인했다.

### 7번. `1e20` float 루프 → "아니오" ✅, 이유 ❌

```c
float f1 = 1e20, f2 = 10;
while (f1 > 1e19) f1 -= f2;
return f1;
```

- **정답**: 아니오 — **무한 루프**에 빠져서 리턴하지 못한다.
- 족보 이유 "f1이 round 되어 0이 되기 때문" ❌: 0이 되면 오히려 루프가 끝난다.
- **핵심 이유**: float의 가수는 23비트(유효숫자 약 7자리)라서, 1e20 근처에서 표현 가능한 수의 간격은 약 2⁴³ ≈ 8.8 × 10¹²이다. 10을 빼도 그 간격보다 훨씬 작으므로, 결과를 반올림(round-to-nearest)하면 **다시 1e20**이 된다. f1이 줄지 않으니 `f1 > 1e19`가 영원히 참이다.

> 모범 답안: f1이 매우 커서 float 정밀도가 부족하다. `f1 - 10`이 반올림되어 f1과 같은 값이 되므로 f1이 감소하지 않고 무한 루프가 된다.

### 8번. 8비트 미니 float (Sign 1 / Exponent 3 / Mantissa 4) ✅

**(1) Bias** = 2^(3−1) − 1 = **3**

**(2) `1 010 1000`의 값** = **−0.75**
- S = 1 → 음수
- e = `010` = 2 → 정규화 값(e가 0도 아니고 전부 1도 아님) → E = e − bias = 2 − 3 = **−1**
- M = 1.f = 1.1000(2) = **1.5**
- 값 = −1.5 × 2⁻¹ = **−0.75**

**(3) 가장 큰 정규화 값** = **15.5**
- e는 `111`(특수값용)을 쓸 수 없으므로 최대 `110` = 6 → E = 6 − 3 = **3**
- f = `1111` → M = 1.1111(2) = 1 + 15/16 = **1.9375**
- 값 = 1.9375 × 2³ = **15.5**

## 족보2

### 1번. `funny` 디스어셈블 → C

```
+0:  jmp  0xa <funny+10>      # 먼저 조건 검사로 점프 (jump to middle)
+2:  add  $0x1, %rdi          # x++
+6:  sub  $0x1, %rsi          # y--
+10: cmp  $0xa, %rsi          # y - 10 계산 → 플래그만 설정
+14: jg   0x2 <funny+2>       # y > 10 이면 루프 몸체로
+16: lea  (%rdi,%rsi,1), %rax # return x + y
+20: retq
```

**(1) 빈칸** → 족보 답 `if (y > 10)` ❌ → 정답:
```c
long funny(long x, long y)
{
    while (y > 10)
    {
        x++;
        y--;
    }
    return x + y;
}
```
- `jg`가 **뒤쪽 주소(+2)로 점프**한다 → 반복문이다. `if`라면 뒤로 가는 점프가 없다.
- 맨 앞 `jmp`가 조건 검사로 먼저 간다 → 몸체를 실행하기 전에 조건을 먼저 보는 **while**이다 (do-while이면 맨 앞 `jmp`가 없다).
- `jg`는 signed 비교 → `long` 타입과 맞다.
- `lea (%rdi,%rsi,1), %rax` = `x + y`. 족보 답 `x++`, `y--`, `x+y`는 맞다.

**(2) `%rsi = 0xb`일 때 `cmp $0xa, %rsi` 직후 플래그** ⬜
- cmp는 `%rsi − 0xa` = 11 − 10 = **1**을 계산하고 결과는 버린다.
- **ZF = 0**: 결과가 0이 아님
- **SF = 0**: 결과가 양수 (MSB 0)
- **OF = 0**: 양수 − 양수라서 signed 오버플로우가 날 수 없음
- (참고: CF = 0, 11 ≥ 10이라 unsigned borrow 없음)
- 확인: `jg` 조건 = `~(SF ^ OF) & ~ZF` = 1 → 점프한다 (11 > 10 이므로 맞음)

### 2번. float/double → int 범위 초과 ✅

```c
float f = 1e10;
double d = f;
int a = (int)f;   printf("%x", a);
a = (int)d;       printf("%x", a);
```
- 정답: float → int: **`80000000`**, double → int: **`80000000`**
- 1e10은 int 최댓값(약 2.1 × 10⁹)보다 크다.
- C 표준에서는 정의되지 않은 동작이지만, x86-64의 변환 명령(`cvttss2si`, `cvttsd2si`)은 범위를 넘으면 **"integer indefinite" 값 `0x80000000`(TMin)**을 낸다.
- 부분 점수용 설명: "int로 표현할 수 없어 TMin(−2147483648)이 출력된다."
- 참고: Mac(arm64)에서 실행하면 `7fffffff`(포화)가 나오지만, 시험은 x86-64 기준이다.

### 3번. unsigned `length - 1` 버그 ✅

```c
float foo(float a[], unsigned length) {
    int i; float result = 0;
    for (i = 0; i <= length-1; i++) result += a[i];
    return result;
}
```

**(1)** `$ gcc -m64 -o myprog -g3 foo.c` ✅
- `-o myprog`: 실행 파일 이름 지정, `-g3`: 디버깅 정보 레벨 3 (매크로 정보까지 포함). 순서는 바뀌어도 된다.

**(2) 원인** ✅
- `length`가 unsigned이므로 length = 0이면 `length - 1` = 0 − 1 = **UMAX(4294967295)**가 된다.
- 비교 `i <= length-1`에서 `i`도 unsigned로 바뀌므로 **항상 참**이다.
- `i`가 배열 범위를 넘어 계속 증가하다가 접근할 수 없는 메모리를 읽어 **segmentation fault**가 난다.

**(3) 해결** ✅
- `unsigned length`를 `int length`로 바꾼다. 또는
- 조건을 `i < length`로 바꾼다 (length = 0이면 바로 끝남).

### 4번. extern과 분할 컴파일 ⬜

> 모범 답안: 프로그램을 여러 `.c` 파일로 나누어 따로 컴파일(분할 컴파일)할 때, **다른 파일에 정의된 전역 변수(또는 함수)를 현재 파일에서 사용하려면** `extern`으로 선언한다. `extern`은 메모리를 할당하지 않는 선언일 뿐이고, 실제 정의와의 연결은 **링커가 심볼 해결 단계에서** 한다.

```c
// a.c
int count = 0;          // 정의 (메모리 할당)
// b.c
extern int count;       // 선언 (a.c의 count를 사용)
```
- 전역 `static` 변수는 `extern`으로 가져올 수 없다 (족보1 1-(2)와 연결).

### 5번. INT_MIN 연산 출력 ⬜

```c
int x = -2147483648;   // INT_MIN
```

| 출력            | 정답            | 이유                                    |
|-----------------|-----------------|-----------------------------------------|
| `x-1` (%d)      | `2147483647`    | `0x80000000 − 1 = 0x7FFFFFFF` (넘어감)  |
| `-x` (%d)       | `-2147483648`   | `~x + 1 = 0x7FFFFFFF + 1 = 0x80000000`  |
| `(unsigned)x`   | `2147483648`    | 비트 그대로 unsigned로 해석 (2³¹)       |
| `~x+x` (%d)     | `-1`            | `~x + x`는 모든 비트가 1 = `0xFFFFFFFF` |

- 정답: `1: 2147483647`, `2: -2147483648`, `3: 2147483648`, `4: -1`
- `~x + x = -1`은 x에 관계없이 항상 성립한다 (x와 ~x는 비트가 서로 반대라 더하면 자리올림 없이 전부 1).
- 실행해서 확인했다.

### 6번. 8비트 미니 float (Sign 1 / Exponent 5 / Mantissa 2) ⬜

> PDF에서 세부 질문이 잘려 보이지 않는다. 족보1 8번과 같은 형식(bias, 비트 패턴 값, 최대 정규화 값)일 가능성이 높으므로 자주 나오는 값을 모두 정리한다.

- **Bias** = 2^(5−1) − 1 = **15**
- **가장 큰 정규화 값**: e = `11110` = 30 → E = 15, M = 1.11(2) = 1.75 → 1.75 × 2¹⁵ = **57344**
- **가장 작은 양의 정규화 값**: e = `00001` → E = 1 − 15 = −14, M = 1.00 → **2⁻¹⁴**
- **가장 큰 비정규화 값**: e = `00000` → E = 1 − bias = −14, M = 0.11(2) = 0.75 → **0.75 × 2⁻¹⁴ = 3 × 2⁻¹⁶**
- **가장 작은 양의 비정규화 값**: M = 0.01(2) = 0.25 → **2⁻¹⁶**
- **+∞** = `0 11111 00`, **NaN** = `x 11111 (00이 아닌 값)`

비트 패턴 → 값 계산 순서 (어떤 패턴이 나와도 같다):
1. S, e, f로 자른다.
2. e가 전부 0이면 비정규화: E = 1 − bias, M = 0.f
3. e가 전부 1이면 특수값: f = 0이면 ±∞, 아니면 NaN
4. 그 외는 정규화: E = e − bias, M = 1.f
5. 값 = (−1)^S × M × 2^E

### 7번. long → short 변환과 unsigned 비교 ⬜

```c
long x = 0x12345678;
short y = (short) x;
printf("%x\n", y);
printf("%x\n", y < -1U);
```
- **첫째 줄: `5678`**
  - long → short는 **하위 16비트만** 남긴다(truncation) → `0x5678`
  - `0x5678`은 MSB가 0인 양수라서, `%x`로 넘길 때 int로 확장해도 상위가 0 → `5678`
- **둘째 줄: `1`**
  - `-1U` = `0xFFFFFFFF`(UMAX, unsigned)
  - y(0x5678)가 unsigned로 바뀌어 `0x5678 < 0xFFFFFFFF` → 참 → **1**
- 실행해서 확인했다.
- 함정 참고: y가 음수(예: `0x8765`)였다면 부호 확장되어 `ffff8765`가 출력된다.

### 8번. 메모리 표 + mov / lea / movs

```
Address  +0 +1 +2 +3 +4 +5 +6 +7
0x00     AB EE 1E AC D5 8E 10 E7
0x08     F7 84 32 2D A5 F2 3A CA
0x10     83 14 53 B9 70 03 F4 31
0x18     01 20 FE 34 46 E4 FC 52
0x20     4C A8 B5 C3 D0 ED 53 17
%rax = 0x4,  %rsi = 0x2
```

**(1)** `movl 2(%rax), %ebx` → 족보 답 `0x00000010` ❌ → 정답 **`0x84F7E710`**
- 주소 = 4 + 2 = **0x6**, 4바이트 읽기: 0x6 = `10`, 0x7 = `E7`, 0x8 = `F7`, 0x9 = `84`
- little endian → 높은 주소부터 읽으면 **`0x84F7E710`**
- (참고: `movl`은 `%rbx`의 상위 32비트를 0으로 만든다)

**(2)** `leal (%rax,%rax,2), %ecx` → 족보 답 `0x000000A5` ❌ → 정답 **`0x0000000C`**
- lea는 **메모리를 읽지 않는다**. 주소 계산 값 자체가 결과다.
- 4 + 4×2 = 12 = **0xC**
- 족보 답은 주소 0xC의 메모리 값(`A5`)을 읽은 실수다.

**(3)** `movsbw 4(%rax), %dx` → **`0xFFF7`** ✅
- 주소 = 4 + 4 = **0x8**, 1바이트 = `F7` = `1111 0111` → MSB 1
- byte → word(16비트) 부호 확장 → **`0xFFF7`**

## 25년 복기 (문제 원문 없음, 메모 기반)

> 원문이 없어서 메모에 적힌 내용으로 예상 답안을 정리했다.

**1번. 출력값** → `80000000` / `80000000` (메모에 정답으로 표시됨)
- 족보2 2번과 같은 float/double → int 범위 초과 문제로 보인다. 해설은 족보2 2번 참고.

**2번. 오류 찾기** (`float a = 1e20;` ... `while(1) { if (a < 1e9) break; ... }`)
- 메모 작성자는 "TMin" 이라고 써서 틀렸고, 정답은 **반올림(rounding) 문제**였다고 한다.
- 정답 방향: a가 너무 커서 작은 수를 빼도 반올림으로 **a가 그대로** 유지된다 → `a < 1e9`가 영원히 거짓 → **무한 루프**. 해설은 족보1 7번 참고.

**3번. jmp 보고 C 빈칸 채우기** → 족보1 3번, 족보2 1번 유형
- 뒤로 가는 점프가 있으면 반복문, 맨 앞에 조건 검사로 가는 `jmp`가 있으면 `while`/`for`(jump to middle).

**4번. `1000 0000 << 2` 하면 0인가? (OX)** → **O**
- 8비트에서 왼쪽으로 2칸 밀면 1이 밖으로 빠지고 `0000 0000`이 된다.
- 왼쪽 시프트는 오른쪽을 항상 0으로 채운다 (산술/논리 구분은 오른쪽 시프트에만 있음).

**5번. jl, jb의 판단 기준**
- **jl** (jump if less, **signed**): `SF ^ OF` = 1 일 때 점프
  - 이유: 오버플로우가 없으면 SF가 결과의 부호를 그대로 보여 주고, 오버플로우가 나면 부호가 뒤집히므로 OF와 XOR해서 바로잡는다.
- **jb** (jump if below, **unsigned**): `CF` = 1 일 때 점프
  - 이유: unsigned 뺄셈 `a − b`에서 a < b이면 빌림(borrow)이 생겨 CF = 1이 된다.

**6번. 심볼 테이블을 쓰는 이유 두 가지**
1. **심볼 해결(symbol resolution)**: 링커가 각 오브젝트 파일의 심볼 테이블을 보고, 한 파일에서 참조한 외부 함수·변수를 다른 파일의 정의와 연결한다.
2. **재배치(relocation)**: 링커가 여러 오브젝트 파일을 합치면서 각 심볼의 최종 주소를 정하고, 그 심볼을 참조하는 코드의 주소를 고친다.
- (보충: 디버거(gdb)가 함수·변수 이름을 주소와 연결하는 데에도 쓴다.)
- 심볼 테이블은 **어셈블러가 생성**하고 이름, 타입, 주소, bind(local/global), size를 담는다.

**7번. float 8비트로 구하기** → 족보1 8번, 족보2 6번 유형. 위 해설 참고.

**8번. C 코드 보고 어셈블리 쓰기 (`movswl`)**
- `movswl` = **mov + sign extend + word(16) → long(32)**
- 이런 C 코드에서 나온다:
  ```c
  int f(short *p) { return *p; }   // short → int 부호 확장
  ```
  ```
  movswl (%rdi), %eax
  ret
  ```
- 대응표: `char→int` = `movsbl`, `unsigned char→int` = `movzbl`, `short→long` = `movswq`, `int→long` = `movslq`(`cltq`)
- signed면 `movs`(MSB 복제), unsigned면 `movz`(0 채움)

**9번. 주소 문제** → 족보1 5번, 족보2 8번 유형
- 풀이 순서: ① 주소 계산 (`D(Rb,Ri,S)` = D + Rb + Ri×S, D는 10진수인지 확인) → ② lea면 메모리 안 읽고 끝 → ③ 크기(b/w/l/q)만큼 바이트 읽기 → ④ little endian으로 뒤집기 → ⑤ movs/movz 확장, 32비트 목적지면 상위 0.
