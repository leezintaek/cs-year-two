## 0. 족보 단골 체크리스트 (먼저 볼 것)

- [ ] **8비트 미니 float**: bias, 비트 패턴 → 값, 최대 정규화 값 (족보 3개 모두 출제)
- [ ] **메모리 표 + mov/lea/movs**: little endian, lea는 메모리를 안 읽음, movl은 상위 0
- [ ] **jmp → C 빈칸**: 맨 앞이 `jmp`(test로 점프)면 `while`
- [ ] **float → int 범위 초과**: x86-64에서 `0x80000000`
- [ ] **`1e20 - 10`**: 반올림으로 다시 1e20 → 무한 루프
- [ ] **INT_MIN 출력**: `x-1` = INT_MAX, `-x` = INT_MIN, `~x+x` = −1, `2*x` = 0
- [ ] **signed/unsigned 섞인 비교**: 무조건 unsigned로 바꿔서 비교
- [ ] **심볼 테이블 용도**: 심볼 해결 + 재배치 (링커가 사용)
- [ ] **jl / jb 기준**: jl = `SF ^ OF` (signed), jb = `CF` (unsigned)
- [ ] **static / extern**, gdb `disas 함수명`, `gcc -o myprog -g3 foo.c`

## 1. 컴파일 시스템과 하드웨어 (week1)

**컴파일 4단계**
```
hello.c -[cpp]-> hello.i -[cc1]-> hello.s -[as]-> hello.o -[ld]-> hello
 text              text             text            binary          binary(ELF)
```
- 전처리기(`cpp`): `#include`, `#define`, `#ifdef` 처리 → `.i`  (`gcc -E`)
- 컴파일러(`cc1`): 어셈블리로 번역 → `.s`  (`gcc -S`)
- 어셈블러(`as`): 기계어 오브젝트 파일 → `.o`, **심볼 테이블 생성**  (`gcc -c`)
- 링커(`ld`): **심볼 해결**(외부 참조를 정의와 연결) + **재배치**(주소 조정·결합) → 실행 파일(ELF)
- `.o`는 다른 파일의 함수 참조를 포함할 수 있어서 **혼자서는 실행 불가**

**하드웨어**
- 속도: 레지스터 > SRAM 캐시(~2ns) > DRAM(~15ns) > 디스크(~7ms)
- SRAM: 캐시용, 비트당 트랜지스터 6개, refresh 불필요, 빠르고 비쌈
- DRAM: 메인 메모리, 트랜지스터 1개 + 커패시터, **refresh 필요**, 밀도 높음
- 둘 다 휘발성. Flash는 비휘발성.
- 행 우선 순회 `for(i) for(j)`가 캐시 친화적 (열 우선보다 약 19배 빠름)
- 셸: built-in이 아니면 디스크에서 메모리로 적재 후 CPU가 `main` 실행

## 2. 정수 (week2)

**범위 (w = 32)**
- UMax = `0xFFFFFFFF` = 4294967295
- TMax = `0x7FFFFFFF` = 2147483647
- TMin = `0x80000000` = −2147483648
- 8비트: TMax 127 (`0x7F`), TMin −128 (`0x80`), UMax 255

**2의 보수**
- 음수 만들기: `-x = ~x + 1`
- 항상 `~x + x = −1`
- **TMin의 음수는 TMin** (`-INT_MIN == INT_MIN`)
- B2T: MSB 가중치가 −2^(w−1)

**캐스팅 = 비트는 그대로, 해석만 바뀜**
- signed → unsigned: 음수면 + 2^w (예: −1 → UMAX)
- `unsigned char 200` → `char` → **−56**
- `char a = 100, b = 30; char c = a + b;` → **−126** (130 − 256)

**⚠️ 비교 함정**
- signed와 unsigned가 섞이면 **signed가 unsigned로** 바뀐다. 상수에 `U`가 붙으면 unsigned.
- `-1 < 0U` → 거짓 (UMAX < 0)
- `2147483647U > -2147483647-1` → 거짓 (`0x7FFFFFFF > 0x80000000`)
- `2147483647 > -2147483647-1` → 참 (둘 다 signed)
- `(unsigned)-1 > -2` → 참 (`0xFFFFFFFF > 0xFFFFFFFE`)
- unsigned `length - 1`에서 length = 0이면 UMAX → `i <= length-1`이 항상 참 → segfault

**확장과 축소**
- 확장: unsigned는 0 채움, signed는 **부호 비트 복제** (값 보존)
- 축소: 상위 비트를 버리고 하위만 남김 (값이 바뀔 수 있음)
  - `int 70000 → short` = 4464, `long 0x12345678 → short` = `0x5678`
- `short -1 → unsigned int`: 먼저 sign-extend(`0xFFFFFFFF`) → 4294967295
- `char 0xF0 → unsigned int` = `0xFFFFFFF0`, `(unsigned char)` 먼저 하면 240

**오버플로우**
- unsigned 덧셈: `sum < x`이면 오버플로우
- signed 덧셈: 양수 + 양수 = 음수(양의 오버플로우), 음수 + 음수 = 양수 이상(음의 오버플로우)
  - TMin + TMin = 0 이므로 음의 오버플로우 검사는 `sum >= 0`
- `SHRT_MAX + 1` → −32768, `INT_MIN - 1` → INT_MAX, `2 * INT_MIN` → 0
- 곱셈 검사: `int64_t p = (int64_t) x * y;` → **곱하기 전에 64비트로**. `x * y`는 32비트에서 먼저 넘친다.

**시프트**
- `x << k` = x × 2^k (넘친 비트는 버림). 8비트 `1000 0000 << 2` = 0
- 오른쪽 시프트: unsigned → logical(0 채움, `shr`), signed → arithmetic(MSB 채움, `sar`)
- 산술 시프트는 내림: −25 >> 3 = **−4** (−3 아님)
- 컴파일러는 `x*8` → `shl $3`, `x*24` → `(x<<5) - (x<<3)`처럼 바꾼다.

**endian**
- little endian(x86): LSB가 **낮은 주소**. `0x12345678` → `78 56 34 12`
- big endian(네트워크): MSB가 낮은 주소 → `12 34 56 78`

## 3. 부동소수점 (week3)

**형식: 값 = (−1)^S × M × 2^E**
- single: S 1 / e 8 / f 23, bias = 127
- double: S 1 / e 11 / f 52, bias = 1023
- **bias = 2^(k−1) − 1** (k = 지수 비트 수)

**지수 필드 e에 따른 세 범주**
- 정규화 (e ≠ 0, e ≠ 모두 1): E = e − bias, M = **1.f**
- 비정규화 (e = 0): E = **1 − bias**, M = **0.f** (hidden bit 없음)
  - ±0도 여기 포함 (f = 0)
  - single 최소 양의 비정규화 값 = 2⁻²³ × 2⁻¹²⁶ = **2⁻¹⁴⁹**
- 특수값 (e = 모두 1): f = 0이면 ±∞, f ≠ 0이면 NaN

**10진수 → 비트 패턴 순서**
1. 2진수로 바꾼다 (소수부는 ×2 반복)
2. 1.xxx × 2^E로 정규화
3. e = E + bias, f = 소수점 아래 (hidden 1 제외)
4. S | e | f 이어 붙인 뒤 4비트씩 끊어 hex로
- 예: 15.75 = 1111.11 = 1.11111 × 2³ → `0x417C0000`
- 예: −6.25 → `0xC0C80000`, `0xC1680000` → −14.5, `0x3F400000` → 0.75

**미니 float 예시 (Sign 1 / Exp 3 / Mantissa 4)**
- bias = 2² − 1 = 3
- `1 010 1000` → E = 2 − 3 = −1, M = 1.1 → **−0.75**
- 최대 정규화 값: e = `110`, f = `1111` → 1.1111 × 2³ = **15.5**
- 최소 양의 정규화 값: e = `001` → 1.0 × 2⁻² = 0.25
- 최대 비정규화 값: e = `000`, f = `1111` → 0.1111 × 2⁻² = 15/64

**반올림: round-to-even**
- 버리는 부분이 절반보다 크면 올림, 작으면 버림
- **정확히 절반**이면 결과 최하위 비트가 0(짝수)이 되게
- 예: `10.01|100` → `10.10`, `10.11|100` → `11.00`, `10.10|100` → `10.10`

**덧셈과 곱셈**
- 덧셈: 작은 지수 쪽 가수를 오른쪽 시프트해 지수 맞춤 → 가수 덧셈 → 정규화 → 반올림
- 곱셈: **지수는 더하고, 가수는 곱하고**, 부호는 XOR → 정규화 → 반올림

**C에서의 함정**
- int → float는 반올림될 수 있음 (가수 23비트), int → double은 정확
- float/double → int: **0 방향 버림** (−2.7 → −2, 1.999 → 1)
- 범위를 넘으면 x86-64에서 **`0x80000000`** (TMin). `(int) 1e10f` → `80000000`
- 0.1, 0.2는 정확히 표현 불가 → `==` 비교 피할 것
- **결합법칙·분배법칙은 보장되지 않는다** (항상 깨지는 건 아님). 교환법칙은 성립.
  - `(3.14f + 1e20f) - 1e20f = 0`, `3.14f + (1e20f - 1e20f) = 3.14`
  - `f1 = 1e20; f1 -= 10;` → 반올림으로 다시 1e20 → `while (f1 > 1e19)` 무한 루프

## 4. 어셈블리 기초 (week5)

**ISA**
- ISA: SW/HW 경계, 명령어 + 상태(레지스터·메모리)를 정의하는 추상 모델
- microarchitecture: ISA의 구현 (Pentium, Athlon은 같은 ISA)
- CISC(x86-64): 가변 길이 1 ~ 15바이트 / RISC(ARM, RISC-V): 고정 4바이트, 명령어 100개 미만

**레지스터와 calling convention**
```
args : %rdi  %rsi  %rdx  %rcx  %r8  %r9   (7th+ on stack)
ret  : %rax
size : %rax(8) %eax(4) %ax(2) %al(1)
       %rdi -> %edi %di %dil   /  %rsi -> %esi %si %sil
       %r8  -> %r8d %r8w %r8b
```
- `%rsp` 스택 포인터, `%rip` 다음 명령어 주소, `%rflags` 플래그

**AT&T 문법**
- `mov src, dst` (Intel은 `mov dst, src`)
- `$` 상수, `%` 레지스터, `()` 메모리
- `$0x104` = 상수 0x104 / `0x104` = 주소 0x104의 메모리

**operand 규칙**
- immediate는 source로만
- **메모리 → 메모리는 한 명령어로 불가** → 레지스터를 거친다

**addressing mode**
- `Imm(rb, ri, s)` → M[Imm + R[rb] + R[ri] × s]
- **s ∈ {1, 2, 4, 8}** (원소 크기: char, short, int, long/포인터)
- 생략된 항은 0. 예: `0x80(,%rdx,2)` → 2 × %rdx + 0x80
- `buf[idx]` (long) → `(%rdi,%rsi,8)`

**도구**
- `gcc -S`, `gcc -c`, `objdump -d`, `objdump -M intel -d`
- gdb: `disas 함수명`, `set disassembly-flavor intel`
- objdump `-t` 크기 = 마지막 명령어 offset + 길이

## 5. 산술 연산과 데이터 이동 (week6)

**suffix**: `b`(1) / `w`(2) / `l`(4) / `q`(8). 생략하면 레지스터 크기로 추론.

**⚠️ mov 크기별 동작** (`%rax = 0x0011223344556677`)
- `movb $-1, %al` → `0x00112233445566ff` (1바이트만)
- `movw $-1, %ax` → `0x001122334455ffff` (2바이트만)
- `movl $-1, %eax` → `0x00000000ffffffff` (**상위 32비트 0**)
- `movq $-1, %rax` → `0xffffffffffffffff`
- 레지스터 목적지 **32비트 연산은 모두** 상위 32비트를 0으로 (`addl`, `xorl` 등도)
  - 이유: common case fast, partial register dependency 제거

**movq vs movabsq**
- 일반 `movq`: 32비트 immediate를 sign-extend
- `movabsq`: 64비트 immediate → **레지스터만** 목적지

**확장**
- signed → `movs` (MSB 복제), unsigned → `movz` (0 채움)
- 이름: `movs/movz` + source suffix + dest suffix (예: `movsbq`, `movzwl`, `movswl`)
- **`movzlq`는 없다** → `movl`이 그 역할
- 컴파일러는 `movzbq` 대신 `movzbl`을 쓴다 (결과 같고 인코딩 짧음)
- `cltq` = `movslq %eax, %rax`
- 축소는 명령어 불필요 (작은 레지스터 이름만 씀). 예: `*charp = y` → `mov %sil,(%rdi)`

**메모리 표 문제 푸는 법**
1. 주소 계산 (`Imm + base + index×s`)
2. 그 주소부터 **크기만큼** 바이트를 읽는다 (b 1, w 2, l 4, q 8)
3. little endian이므로 **뒤집어서** 값으로 만든다
4. 확장(movs/movz)이 있으면 처리하고, 목적지 크기에 맞춰 갱신 (32비트면 상위 0)
- **lea는 메모리를 읽지 않는다** → 주소 계산 값이 그대로 결과

**lea**
- `lea 6(%rax), %rdx` → %rdx = %rax + 6 (메모리 접근 없음, 플래그 변경 없음)
- `&buf[i]` → `lea (%rdi,%rsi,8)`, `x*3` → `lea (%rdi,%rdi,2)`
- `x*48` → `lea (%rdi,%rdi,2)` + `shl $4`

**연산**
- 단항: `inc`, `dec`, `neg`(−D), `not`(~D)
- 이항 `op S, D` → **D = D op S**. ⚠️ `sub S, D` = D − S
- 시프트: `sal`/`shl` 왼쪽, `sar` 산술(signed), `shr` 논리(unsigned)
- `xor %rax, %rax` → 0

**C ↔ 어셈블리 예**
```
arith(x, y, z):            # t1 = x^y; t2 = z*48; t3 = t1 & 0x0F0F0F0F; return t2 - t3;
  xorq  %rsi, %rdi
  leaq  (%rdx,%rdx,2), %rax
  salq  $4, %rax
  andl  $252645135, %edi
  subq  %rdi, %rax
```

## 6. 제어 흐름 (week7)

**condition code**
- CF: unsigned 오버플로우 (carry / borrow)
- ZF: 결과 0
- SF: 결과 음수 (signed)
- OF: signed 오버플로우
- 산술·논리 연산이 자동 설정. **`lea`는 설정 안 함**

**cmp / test (결과 저장 X, 플래그만)**
- `cmp b, a` → **a − b** 계산 (순서 주의!)
- `test b, a` → a & b 계산. `test %rdi, %rdi`로 0인지(ZF)·음수인지(SF) 확인
- `cmp`에서 CF = 1 ⇔ unsigned a < b

**플래그 계산 연습**
- 8비트 `0x90 + 0xA0` = `0x30` → CF 1, ZF 0, SF 0, OF 1
- 8비트 `0x7F + 0x01` = `0x80` → CF 0, SF 1, OF 1
- `cmp $0xa, %rsi` (%rsi = 11) → 1 → ZF 0, SF 0, OF 0

**jump / set / cmov 조건** (`cmp b, a` 기준)
```
je   ZF                 equal
jne  ~ZF                not equal
jg   ~(SF^OF) & ~ZF     a > b   signed
jge  ~(SF^OF)           a >= b  signed
jl   SF^OF              a < b   signed
jle  (SF^OF) | ZF       a <= b  signed
ja   ~CF & ~ZF          a > b   unsigned
jae  ~CF                a >= b  unsigned
jb   CF                 a < b   unsigned
jbe  CF | ZF            a <= b  unsigned
```
- greater/less(g, l) = **signed**, above/below(a, b) = **unsigned**
- `SF ^ OF`인 이유: 오버플로우가 나면 부호가 뒤집히므로 OF로 보정

**C 구조별 어셈블리 패턴**
- `if`: 조건이 **거짓**이면 body를 건너뛰는 점프 → C의 `>`가 `jle`로 나타남
- `if-else`: then 끝에 **무조건 `jmp`**로 else를 건너뜀
- `do-while`: body → test → 참이면 body로 (맨 앞에 `jmp` 없음)
- `while` / `for`: **맨 앞에 test로 가는 `jmp`** (jump to middle)
  - `for`는 init → `jmp test` → body → update → test
- 족보2 `funny`: 맨 앞 `jmp` → **while** (`if` 아님)
```c
long funny(long x, long y) {
    while (y > 10) { x++; y--; }
    return x + y;
}
```

**cmov (conditional move)**
- 양쪽 값을 **모두 계산**한 뒤 조건에 맞는 것을 고름 → 분기가 없어 pipeline이 안 끊김
- 쓰면 안 되는 경우: 계산이 비쌈 / **위험함** (`p ? *p : 0`에서 NULL 역참조) / 부작용
- `-Og`는 분기, `-O1`은 cmov를 쓰는 경우가 많다

**setX**
- 조건이면 **1바이트**를 1, 아니면 0
- int/long으로 반환하려면 `movzbl %al, %eax`
- `return x > 100;` (-O1) → `cmp $0x64,%rdi` / `setg %al` / `movzbl %al,%eax`

## 7. static / extern / GNU 도구 (족보 출제)

- 전역 `static`: **이 파일 안에서만** 보임 (다른 파일에서 접근 불가)
- 지역 `static`: 함수가 끝나도 값 유지, 초기화는 한 번만
  - 족보1: `useStaticLocal()` 두 번 호출 → 100, 101 / 101, 102
- `extern`: 다른 파일(모듈)에 정의된 전역 변수·함수를 쓰겠다는 선언. 분할 컴파일 후 링커가 연결
- 블록 안 지역 변수는 바깥 변수를 가린다 (블록이 끝나면 다시 바깥 값)
- `gcc -m64 -o myprog -g3 foo.c` (실행 파일 이름 myprog, 디버깅 레벨 3)
- gdb 디스어셈블: `disas 함수명` (`objdump -d`는 셸 명령)
- 심볼 테이블: 어셈블러가 생성 (이름, 타입, 주소, bind, size), 링커가 **심볼 해결과 재배치**에 사용
