# 강의 녹음 요약

## 핵심 원칙

요약본은 **실제 수업에서 말한 내용의 기록**이다. 범위는 녹음이 정하고, 강의 자료는 그 범위 안에서 녹음을 이해하고 교정하는 데만 쓴다. 강의 자료에는 수업 진도보다 많은 내용이 들어 있을 수 있기 때문이다.

## 절차

1. **폴더 확인**: 사용자가 말한 `_workspace/<과목>/<강의이름>/` 폴더를 쓴다. 어느 폴더인지 알 수 없으면 묻는다. 저장소 루트에 `<과목>` 폴더가 없으면 새로 만들지 말고 묻는다.
2. **전사**: 녹음에 대응하는 `<녹음이름>.transcript.md`가 없거나 PDF가 있는데 `slides.md`가 없으면 저장소 루트에서 백그라운드로 실행한다. 이미 있는 전사문은 건너뛴다.
   ```
   _tools\transcription\.venv\Scripts\python _tools\transcription\transcribe.py <폴더>
   ```
3. **읽기**: 전사문 전체를 먼저 읽고, 그다음 `slides.md`를 읽는다.
4. **대조**: 슬라이드마다 수업에서 다뤘는지 판단한다. 강의가 어디까지 진행됐는지, 건너뛴 부분이 있는지 전사문 기준으로 확인한다.
5. **작성**: `<과목>/summaries/<강의이름>.md`에 저장한다. `summaries` 폴더가 없으면 만들고, 같은 이름의 파일이 있으면 덮어쓰기 전에 사용자에게 확인한다. `weekN/lecture_summary.md` 등 기존 파일은 수정하지 않는다. 녹음, PDF, 전사문, `slides.md`는 작업 폴더에 그대로 둔다.

## 내용의 출처

| 내용 | 처리 |
|---|---|
| 수업에서 설명한 내용 | 본문에 정리 |
| 교수님이 강조한 점, 시험·과제 언급, 비유와 예시 | 본문에 포함 |
| 수업에서 언급한 슬라이드의 코드·표·그림 | 설명에 필요한 만큼 본문에 인용 |
| 전사 오인식 (`포시적 콜` → `procedure call`) | 슬라이드 용어로 교정 |
| 슬라이드에만 있고 수업에서 다루지 않은 내용 | 본문에 넣지 않고, "수업에서 다루지 않은 슬라이드"에 번호와 제목만 기록 |
| 전사가 불분명하고 슬라이드로도 확인되지 않는 내용 | `(확인 필요)` 표시 후 전사 내용 그대로 기록 |

## 표기

기술 용어는 영어로, 설명은 한국어로 쓴다. 전사문에 한글 음차로 적힌 용어도 영어로 바꾼다.

> `call`은 return address를 stack에 push한 뒤 callee로 jump한다. 그래서 `%rsp`가 8 감소한다.

- `스택 포인터`가 아니라 `stack pointer`, `컬링 컨벤션`이 아니라 `calling convention`으로 쓴다.
- 명령어, 레지스터, 코드는 백틱으로 감싼다.
- 표는 VS Code에서 마크다운 원문으로 볼 때 세로선(`|`)이 줄마다 맞도록 공백으로 정렬한다. 한글 등 전각 문자는 2칸, 영문·숫자·기호는 1칸으로 계산한다.

## summary.md 구조

```markdown
# <강의 제목> 요약

- 녹음: A = `<파일명>` (날짜, 길이) / B = ...
- 진도: 슬라이드 N–M

> 이번 강의의 핵심 1–3문장

## <주제>  `A 12:07`
수업에서 다룬 흐름대로 정리한 내용

## 강조 사항
시험·과제 언급과 교수님이 강조한 점. 없으면 이 절을 생략한다.

## 수업에서 다루지 않은 슬라이드
- 슬라이드 25: <제목>
```

- 절은 슬라이드 순서가 아니라 수업에서 다룬 주제 단위로 나눈다.
- 타임스탬프는 `A mm:ss` 형식으로 쓴다. 녹음이 하나여도 `A`를 붙인다.
- PDF가 없으면 진도 줄과 "수업에서 다루지 않은 슬라이드" 절을 뺀다.
