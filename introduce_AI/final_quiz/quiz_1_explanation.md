## Q1. Multi-channel convolution (11_1)

**정답:** (1) `[4 −3; 9 5]` (2) 9개 (3) 72개, 2×2, 8장

**(1) channel별로 계산한 뒤 같은 위치끼리 더하고 bias를 더한다**

```
channel 1 (kernel [1 −1; 0 2])
왼쪽 위:   1×1 + 0×(−1) + 3×0 + 1×2 =  3
오른쪽 위: 0×1 + 2×(−1) + 1×0 + 0×2 = −2
왼쪽 아래: 3×1 + 1×(−1) + 0×0 + 2×2 =  6
오른쪽 아래: 1×1 + 0×(−1) + 2×0 + 1×2 = 3

channel 2 (kernel [0 1; 1 −1])
왼쪽 위:   2×0 + 1×1 + 0×1 + 1×(−1) =  0
오른쪽 위: 1×0 + 0×1 + 1×1 + 3×(−1) = −2
왼쪽 아래: 0×0 + 1×1 + 1×1 + 0×(−1) =  2
오른쪽 아래: 1×0 + 3×1 + 0×1 + 2×(−1) = 1

합 + bias 1
[3+0+1   −2−2+1]   =   [4  −3]
[6+2+1    3+1+1]       [9   5]
```

**(2)** `(M² · C_IN + 1) × C_OUT = (2×2×2 + 1) × 1 = 9`

**(3)** `(2×2×2 + 1) × 8 = 72`. 크기는 `(3 + 0 − 2)/1 + 1 = 2`로 2×2 그대로이고, 장수는 output channel 수와 같은 8장이다.

**함정:** bias는 channel마다 하나씩이 아니라 **kernel set(output channel)마다 하나**다. channel 1, 2에 각각 bias를 더해 `+2`를 하면 틀린다.

## Q2. Time window와 weight 크기 (12_2)

**정답:** F

- Window를 늘리면 `y(0), y(1), …`을 반복 계산하는 횟수는 늘어난다. 이것이 RNN의 단점 "계산이 느리다"다.
- 하지만 `Wx`, `Wh`는 **모든 시점에서 재사용(weight sharing)**하므로 크기가 바뀌지 않는다. `Wx`는 `n_inputs × n_neurons`, `Wh`는 `n_neurons × n_neurons`로, window와 무관하다.
- 장점 2 "input이 길어져도 model 크기 불변"이 바로 이 내용이다.

**함정:** 앞부분(계산 횟수 증가)은 맞는 말이라서 전체를 T로 고르기 쉽다.

## Q3. Backpropagation과 vanishing gradient (9_2)

**정답:** (1) 0.0504 (2) 0.0672 (3) 0.004032 (4) `w₂,₀,₀ = 0.39496`, `w₁,₀,₀ = 0.1995968` (5) 12.5배, vanishing gradient

공통으로 쓰는 앞의 두 항:

```
∂L/∂ŷ        = 2(ŷ − y)    = 2(0.7 − 0.5) = 0.4
∂ŷ/∂z₂,₀     = ŷ(1 − ŷ)    = 0.7 × 0.3    = 0.21
두 항의 곱 = 0.084
```

**(1)** `0.084 × o₁,₀ = 0.084 × 0.6 = 0.0504`

**(2)** `0.084 × o₁,₁ = 0.084 × 0.8 = 0.0672`

**(3)** Forward 순서를 거꾸로 따라가며 항을 더 곱한다.

```
∂L/∂w₁,₀,₀ = 0.084 × w₂,₀,₀ × o₁,₀(1 − o₁,₀) × x₀
           = 0.084 × 0.4    × 0.6 × 0.4     × 0.5
           = 0.004032
```

**(4)** `W := W − η · ∂L/∂W`

- `w₂,₀,₀ = 0.4 − 0.1 × 0.0504 = 0.39496`
- `w₁,₀,₀ = 0.2 − 0.1 × 0.004032 = 0.1995968`

**(5)** `0.0504 / 0.004032 = 12.5`. 앞쪽 layer로 갈수록 1보다 작은 항(`0.4`, `0.24`, `0.5`)이 더 곱해져 gradient가 작아진다. 깊어질수록 앞쪽 gradient가 거의 사라지는 것이 **vanishing gradient**다.

**함정:**
- (3)에서 `∂z₂,₀/∂o₁,₀ = w₂,₀,₀`를 빼먹기 쉽다. Output 쪽 weight로 미분할 때는 입력(`o₁,₀`)이 남지만, hidden 출력으로 미분할 때는 weight가 남는다.
- (4)에서 update는 gradient를 **빼는** 것이다. 더하면 loss가 커지는 방향으로 간다.

## Q4. Input/output sequence 유형 (12_2)

**정답:** ②

- (가) 여러 시점 → 값 하나: **seq-to-vec** (마지막 output만 쓰고 나머지 무시)
- (나) 이미지 하나 → 문장: **vec-to-seq** (image captioning)
- (다) 번역: **encoder-decoder**
- (라) N일 → 하루씩 민 N일: **seq-to-seq**

**추가:** 각 시점은 자기 앞의 단어까지만 알 수 있는데, 번역은 문장 끝의 단어가 첫 단어 번역에 영향을 줄 수 있어서 **입력을 끝까지 읽은(encoder) 뒤에 출력(decoder)**해야 하기 때문이다. RNN 단점 3 "미래 input을 반영할 수 없다"를 해결한 구조다.

**함정:** 번역도 many-to-many라서 seq-to-seq로 고르기 쉽다. 수업에서는 번역의 예로 encoder-decoder를 들었다.

## Q5. Stride와 padding이 있는 convolution 코드 (10_2)

**정답:** (a) `P` (b) `(H + 2 * P - M) // S + 1` (c) `S` (d) `M` (e) `np.sum(patch * filt)` (f) 4×4 (g) 3×3, 4~6행, 7행

- (a) 위아래·양옆에 `P` pixel씩 0을 채운다. 수업 코드는 `pad_width=1`이었다.
- (b) `⌊(J + 2P − M) / S⌋ + 1`이다. Python의 `//`는 나눈 뒤 내림하는 연산이라 floor 역할을 한다. (수업 외 보충: `//` 문법)
- (c), (d) stride만큼 건너뛴 위치 `row * S`에서 시작해 kernel 크기 `M`만큼 자른다. 수업 코드는 `S = 1`, `M = 3`이라 `padded[row:row+3, …]`였다.
- (e) patch와 filter를 원소별로 곱해 모두 더한다(weighted sum).

**(f)** `⌊(7 + 2 − 3)/2⌋ + 1 = 3 + 1 = 4` → 4×4

**(g)** `⌊(8 − 3)/2⌋ + 1 = 2 + 1 = 3` → 3×3. 마지막 `row = 2`이면 `r = 4`라서 4, 5, 6행을 덮는다. **7행**은 filter가 들어갈 자리가 없어서 계산에서 빠진다. 이것이 floor를 쓰는 이유다.

**함정:** (c)에 `M`을 넣으면 patch가 겹치지 않게 kernel 크기만큼 건너뛰게 된다. 건너뛰는 간격은 kernel 크기가 아니라 stride다.

## Q10. ReLU와 linear region (9_2)

**정답:** (1) 125개, 53개 (2) 124개, 373개 (3) 3개

**(1)**
- 최대 linear region: `(D + 1)^K = 5³ = 125`
- Parameter: `3D + 1 + (K − 1)D(D + 1) = 13 + 2 × 4 × 5 = 53`

**(2)** Hidden layer 1개는 최대 `D + 1`개 region이므로 `D + 1 = 125`, `D = 124`. Parameter는 `3 × 124 + 1 = 373`이다. 같은 region 수를 deep network는 53개, shallow network는 373개 parameter로 얻는다. 그래서 deep network가 복잡한 데이터에 유리하다.

**(3)** 꺾이는 지점은 `x − 1 = 0 → 1`, `2x − 2 = 0 → 1`, `x − 3 = 0 → 3`이다. 서로 다른 breakpoint는 1과 3 두 개뿐이므로 region은 **3개**다.

**함정:** (3)에서 neuron이 3개라 "최대 4개"를 그대로 답하기 쉽다. 수업에서 "같은 breakpoint를 갖는 neuron이 있으면 그만큼 줄어든다"고 했다. 꺾이는 지점은 `x = −b/w`다.

## Q14. Normalization과 gradient 문제 (9_2)

**정답:** ② ③ ⑤

## Q15. Edge detection filter (10_2)

**정답:** (1) Vertical −24, Horizontal 0, Laplacian 24 (2) 왼쪽이 밝고 오른쪽이 어둡다(bright → dark) (3) 세로 edge

**(1)**

```
Vertical:   (1+1+1) − (9+9+9) = 3 − 27 = −24        (오른쪽 − 왼쪽)
Horizontal: (9+9+1) − (9+9+1) = 0                   (아래 − 위)
Laplacian:  8×9 − (9+9+1 + 9+1 + 9+9+1) = 72 − 48 = 24
```

**(2)** Vertical filter는 왼쪽을 빼고 오른쪽을 더한다. 음수이므로 왼쪽(9)이 밝고 오른쪽(1)이 어둡다.

**(3)** 밝기가 왼쪽과 오른쪽 사이에서 바뀌므로 경계선은 **세로** 방향이다. 위아래 행이 모두 `9 9 1`로 같아서 horizontal filter는 0이 된다. 가로 edge에만 반응하는 filter라서 세로 edge에는 반응하지 않는다. Laplacian은 모든 방향을 보므로 0이 아니다.

**함정:** "vertical filter = 세로 방향 변화를 찾는다"고 외우면 헷갈린다. Vertical filter는 **좌우 차이**를 계산해 **세로로 서 있는 edge**를 찾는다.

## Q16. Sliding window 학습 데이터 (12_2)

**정답:**

```
(1) [x(0), …, x(4)]   → [x(1)[3],  …, x(5)[3]]
(2) [x(24), …, x(28)] → [x(25)[3], …, x(29)[3]]
(3) 25개 (시작 위치 0 ~ 24)
(4) [x(25), …, x(29)] → 마지막 target은 x(30)[3]  (아직 모르는 다음 날 종가)
```

- 각 시점 `x(t)`의 target은 다음 날 종가 `x(t+1)[3]`이다. 그래서 target 쪽이 input보다 한 칸 밀려 있다.
- Training의 target은 알고 있는 데이터 안에 있어야 하므로, 마지막 target이 `x(29)[3]`인 `x(24)~x(28)`이 마지막 training set이다.
- 수업 예시(99일치, window 7)에서 training의 마지막이 `[x(91)…x(97)] → [x(92)[3]…x(98)[3]]`, testing이 `[x(92)…x(98)] → […x(99)[3]]`였던 것과 같은 구조다.

**함정:** target `[3]`은 4개 값 중 4번째, 즉 **Close**다. index가 0부터 시작한다는 점에 주의.

## Q17. Input channel과 feature map (11_1)

**정답:** T

- Parameter는 `(M² · C_IN + 1) × C_OUT`이므로 `C_IN`이 커지면 늘어난다.
- Channel별 결과는 모두 더해져 한 장이 되므로, 출력 장수는 `C_OUT`, 크기는 `⌊(J + 2P − M)/S⌋ + 1`로만 정해진다. 그래서 LeNet-5를 CIFAR에 쓸 때 input channel을 3으로 바꿔도 뒤쪽 feature map은 바뀌지 않는다.

## Q18. LeNet-5를 CIFAR-100에 적용 (11_1)

**정답:**

```
(1) self.c1     = nn.Conv2d(3, 6, kernel_size=5, stride=1, padding=0)   ← input channel 3, padding 0
    self.output = nn.Linear(84, 100)                                     ← class 100

(2) c1:     (5×5×3 + 1) × 6   = 76 × 6   = 456
    c3:     (5×5×6 + 1) × 16  = 151 × 16 = 2,416   (변화 없음)
    output: 84 × 100 + 100    = 8,500

(3) c1: (32 + 4 − 5) + 1 = 32 → S2: 16 → c3: 16 − 5 + 1 = 12 → S4: 6
    flatten: 6 × 6 × 16 = 576 → self.f5 = nn.Linear(400, 120)에서 크기가 맞지 않음

(4) 84 × 20 + 20 = 1,700
```

- MNIST(28×28)는 32에 맞추려고 padding 2를 넣었지만, CIFAR는 이미 32×32라서 padding 0이다.
- 바꿔야 할 것은 수업에서 말한 세 가지: padding, input channel, class 수.

**함정:** padding만 바꾸고 input channel을 1로 두면 RGB 3 channel 입력이 들어갈 수 없다. 반대로 input channel만 바꾸면 (3)처럼 flatten 크기가 576이 된다.

## Q19. Outlier와 min-max normalization (9_2, 10_1)

**정답:** (1) 0.05 (2) `μ = 20`, `σ ≈ 30.07`, 6 → −0.47 (3) 0.67 (4) min-max

```
(1) (6 − 2) / (80 − 2) = 4 / 78 ≈ 0.051

(2) μ = (2 + 4 + 6 + 8 + 80) / 5 = 20
    편차 제곱: 18² + 16² + 14² + 12² + 60² = 324 + 256 + 196 + 144 + 3600 = 4520
    σ = √(4520 / 5) = √904 ≈ 30.07
    (6 − 20) / 30.07 ≈ −0.47

(3) (6 − 2) / (8 − 2) = 4 / 6 ≈ 0.67
```

**(4)** **Min-max**가 outlier의 영향을 크게 받는다. Outlier 80이 `x_max`가 되면서 나머지 값 2, 4, 6, 8이 0~0.08이라는 아주 좁은 구간에 몰린다. outlier가 없을 때 0.67이던 6이 0.05로 줄어든 것이 그 예다.

## Q20. Hidden state RNN의 parameter와 한계 (12_2)

**정답:** (1) `Wx` 4×64, `Wh` 64×64, `b_h` 64, `Wy` 64×1, `b_y` 1 (2) 4,481 (3) parameter 수는 그대로, `H(t)` 계산은 30번 (4) 아래 참고

**(2)** `256 + 4,096 + 64 + 64 + 1 = 4,481`

**(3)** Weight를 모든 시점에서 재사용하므로 parameter 수는 그대로 4,481이다. 계산은 window만큼, 즉 30번 반복한다.

**(4)** 30 시점 전의 정보는 현재까지 오는 동안 `Wh`가 30번 곱해져서 온다. Weight가 보통 1보다 작으므로 여러 번 곱해지면 **희미해진다**. 그래서 기본 RNN cell은 가까운 시점의 짧은 pattern만 잘 학습한다(memory cell의 한계, RNN 단점 2).

**함정:** (2)는 수업 식(bias 하나씩) 기준이다. (수업 외 보충) PyTorch의 `nn.RNN`은 bias를 `b_ih`, `b_hh` 두 개 두기 때문에 `torchsummary`로 보면 64개가 더 많게 나온다.
