## 지난 시간 연결: 일반적인 CNN 구조  `A 00:00`

Convolution과 pooling으로 feature를 충분히 뽑은 뒤 전부 flatten해서 fully connected layer(dense layer)를 거치는 것이 일반적인 CNN architecture다. 지난 시간까지는 흑백(grayscale) 이미지만 다뤘고, 오늘은 color 이미지처럼 channel이 여러 개인 경우를 다룬다.

## Multi-dimensional convolution: input channel  `A 01:23`

- Color 이미지는 pixel마다 R, G, B 값 3개를 가진다. R 값끼리 모은 행렬, G 값끼리, B 값끼리 모은 행렬을 각각 **channel**이라 한다.
- `J × K` pixel, `C_IN`개 channel인 이미지 → input feature는 `J × K × C_IN`개
- Kernel도 input channel마다 따로 필요하다(R용, G용, B용). 따라서 filter 크기는 `M × M × C_IN`
  - Weight parameter: `M² · C_IN`
  - Bias parameter: `1`
  - Kernel을 이미지 전체에 재사용하므로 **이미지 크기와는 무관**하다.

**계산 방법**: channel마다 해당 kernel로 convolution을 한 뒤, 같은 위치의 값을 **모두 더해서** feature map 한 장을 만든다.

**예시: input channel 2개** `A 05:35` (3×3 input, 2×2 kernel, padding 0, stride 1 → `(3 + 0 − 2)/1 + 1 = 2`, 2×2 feature map)

- 첫 번째 channel (input `0..8`, kernel `[0 1; 2 3]`), 왼쪽 위: `0×0 + 1×1 + 3×2 + 4×3 = 19`
- 두 번째 channel (input `1..9`, kernel `[1 2; 3 4]`), 왼쪽 위: `1×1 + 2×2 + 4×3 + 5×4 = 37`
- 합: `19 + 37 = 56`
- 오른쪽 위도 같은 방법으로 `(1×0 + 2×1 + 4×2 + 5×3) + (2×1 + 3×2 + 5×3 + 6×4) = 25 + 47 = 72`
- 결과 output: `[56 72; 104 120]`

**핵심** `A 09:48`: input channel이 3개든 10개든 결국 다 더해지므로 **feature map의 장수와 크기는 input channel 수의 영향을 받지 않는다.** 크기는 여전히 width/height, padding, kernel size, stride로만 정해진다.

```
feature map 크기 = ⌊(J + 2P − M) / S⌋ + 1      (padding 0, stride 1이면 J − M + 1)
```

## Output channel  `A 10:52`

- Edge detection에서 봤듯이 filter마다 잡아내는 feature가 다르다(horizontal, vertical 등). **한 filter(kernel set)는 한 가지 feature만** 학습할 수 있다.
- 그래서 kernel set을 여러 개 만들어 "너는 horizontal, 너는 vertical"처럼 역할을 나눈다. 이 kernel set의 개수가 **`C_OUT`(output channel 수)**이고, feature map도 `C_OUT`장 생긴다.
- Filter 하나는 fully connected network의 hidden node 하나와 비슷하다. Hidden node는 모든 입력에 대한 weighted sum이고, filter는 특정 영역(patch)에 대한 weighted sum이다.
- 정리하면
  - **Input channel**: RGB처럼 입력이 가진 여러 성분을 다루기 위한 것 (계산 후 더해짐)
  - **Output channel**: 여러 종류의 feature를 학습하기 위해 여러 filter를 쓰는 것 (feature map 장수가 됨)

```
filter 차원 = M × M × C_IN × C_OUT
parameter 수 = (M² · C_IN + 1) × C_OUT
```

## LeNet-5 다시 보기: 크기와 parameter 계산  `A 17:05`

LeNet-5는 32×32, channel 1(grayscale) 이미지를 입력으로 받도록 설계됐다. 지난 시간에 넘어갔던 "Maps" 열이 바로 output channel 수다.

| Layer | 계산                           | 출력         | Parameter                       |
|-------|--------------------------------|--------------|---------------------------------|
| C1    | `(32 + 0 − 5)/1 + 1 = 28`      | `28×28×6`    | `(5×5×1 + 1)×6 = 156`           |
| S2    | `(28 + 0 − 2)/2 + 1 = 14`      | `14×14×6`    | `0`                             |
| C3    | `(14 + 0 − 5)/1 + 1 = 10`      | `10×10×16`   | `(5×5×6 + 1)×16 = 2,416`        |
| S4    | `(10 + 0 − 2)/2 + 1 = 5`       | `5×5×16`     | `0`                             |
| C5/F5 | flatten `5×5×16 = 400`         | `120`        | `400×120 + 120 = 48,120`        |
| F6    | -                              | `84`         | `120×84 + 84 = 10,164`          |
| Out   | -                              | `10`         | `84×10 + 10 = 850`              |

- Pooling은 channel마다 따로 적용하므로 **장수는 그대로**, 크기만 줄어든다. `A 20:08`
- C3의 input channel 6은 앞 layer의 output channel 6에서 온 것이다.
- **슬라이드 20의 `(5×5×6×10) + 16 = 1516`은 무시**하라고 하셨다. 원래 LeNet은 6장을 전부 더하지 않고 3장씩 묶는 특수한 연결(표의 X)로 parameter를 줄였는데, 이는 그 모델 고유의 구조라서 잊어도 된다. 일반 convolution layer라면 `(5×5×6 + 1)×16`이 맞다. `A 23:18`
- 지난주 슬라이드에서 잘못 표시된 부분이 있었으니 오늘 슬라이드 기준으로 보라고 하셨다. `A 20:08`

**Fully connected = 입력과 같은 크기의 convolution** `A 24:20`

5×5×16 출력에서 120으로 가는 layer는 두 가지로 표현할 수 있다.

1. Flatten해서 400개 입력 → 120 neuron fully connected: `400 × 120 + 120 = 48,120`
2. 5×5 kernel, input channel 16, output channel 120인 convolution: `(5×5×16 + 1) × 120 = 48,120`

Kernel 크기가 입력 크기와 같으면 출력은 `(5 − 5)/1 + 1 = 1`, 즉 1×1이고 이는 입력 전체에 대한 weighted sum이다. Kernel set 하나가 neuron 하나의 역할을 하므로, 120세트는 neuron 120개짜리 fully connected layer와 같다. 그래서 LeNet-5를 검색하면 이 layer가 convolution으로도, fully connected로도 나온다.

**식을 외우는 법** `A 36:57`: "filter size × input channel + bias 1, 이것이 output channel 수만큼". 힘들면 공식처럼 외워도 되지만, 이해하면 훨씬 쉽게 외워진다(교수님도 식을 외우고 있지는 않다고 하심).

## LeNet-5 구현 (MNIST)  `A 31:45`

```python
self.c1 = nn.Conv2d(1, 6, kernel_size=5, stride=1, padding=2)
self.c3 = nn.Conv2d(6, 16, kernel_size=5, stride=1, padding=0)
self.c5 = nn.Conv2d(16, 120, kernel_size=5, stride=1, padding=0)
self.pool = nn.AvgPool2d(kernel_size=2, stride=2)
self.f6 = nn.Linear(120, 84)
self.output = nn.Linear(84, num_classes)
```

- `nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)` — 이제 앞의 두 인자가 input/output channel임을 이해할 수 있다.
- MNIST는 `28×28×1`인데 LeNet-5는 32×32 입력용이므로 **`padding=2`**로 32×32를 맞춘다. 입력이 32×32라면 padding 0, 30×30이라면 padding 1이 된다. `A 32:46`
- `torchsummary.summary(model, input_size=(1, 28, 28))`로 각 layer의 output shape과 parameter 수(156, 2,416, 48,120, 10,164, 850)를 확인할 수 있으며, 위에서 손으로 계산한 값과 같다.
- **Feature map 크기와 channel 수를 알아야 하는 이유**: 그래야 flatten 후 `Linear(400, 120)`인지 `Linear(300, 120)`인지 숫자를 정할 수 있다. `A 34:54`
- **Implementation (2)**: `c5` convolution 대신 `self.f5 = nn.Linear(400, 120)`을 써도 된다. 단, fully connected는 flatten 이후에 와야 하므로 `forward`에서 `torch.flatten` **아래로** 위치가 옮겨진다. Parameter 수(48,120)는 동일하다. `A 35:55`

## CIFAR-10과 CIFAR-100  `A 37:59`

MNIST, Fashion-MNIST는 흑백이었고, 이제 color 데이터셋이다.

- **CIFAR-10**: `32×32` RGB color 이미지, 10개 class(airplane, automobile, bird, cat, …), 총 60,000장(class당 6,000장), training 50,000 / test 10,000
  - 개수는 안 외워도 되지만 **32×32, RGB 데이터셋이라는 것은 기억**하라고 하셨다.
- **CIFAR-100**: 100개 class, class당 600장(training 500 / test 100)
  - Label이 두 개다: 세부 class 100개(fine label)와 **superclass 20개**(coarse label). Superclass 하나 아래에 class가 5개씩 묶여 있다.
  - 예: bicycle, bus, motorcycle, pickup truck, train → superclass `vehicles 1` / bee, beetle, butterfly, caterpillar, cockroach → `insects`
  - 그래서 100-class 분류도, 20-class 분류도 할 수 있다.

**LeNet-5를 CIFAR에 쓰려면** `A 40:07`

1. **Padding**: MNIST(28)는 32로 맞추려고 2를 넣었지만 CIFAR는 이미 32×32이므로 `padding=0`
2. **Input channel**: 첫 convolution layer의 input channel을 1 → **3**으로
   - 뒤쪽 feature map 개수나 크기는 바뀌지 않는다(input channel은 계산 후 더해지므로).
3. CIFAR-100이면 마지막 output layer를 **100**(superclass면 20)으로

Color 이미지라고 항상 RGB 3 channel인 것은 아니다. 투명도까지 4 channel이거나, 명도·채도 등 다른 표현일 수도 있으므로 데이터에 맞게 input channel 수를 정하면 된다. `A 42:19`

**CIFAR-10 feature map 크기 예시** (`32×32`, kernel `3×3`) `A 43:19`

- Padding 없음: `32 − 3 + 1 = 30` → `30×30`
- Padding 2: `32 + 2×2 − 3 + 1 = 34` → `34×34` (위아래·양옆이라 2를 두 번 더함)
- Padding 2, stride 2: `⌊(32 + 2×2 − 3)/2⌋ + 1 = 17` → `17×17`

**Normalization** `A 43:19`

```python
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.4914, 0.4822, 0.4465), (0.2023, 0.1994, 0.2010))
])
```

- 필수는 아니지만(없어도 돌아감) 입력 데이터의 범위를 맞추기 위해 보통 한다. 숫자는 외울 필요 없다.
- `transforms.Normalize(mean, std)`는 channel별 평균과 표준편차를 받아 `(input − mean) / std`, 즉 Z-score normalization을 한다. R, G, B channel마다 **따로** 적용된다.
- 적용 후에도 shape(`32×32×3`)은 그대로이고, 각 channel의 평균이 0, 표준편차가 1이 된다.

## AlexNet (예고)  `A 45:25`

- ImageNet(1,000개 class로 labeling된 이미지 데이터셋) 대회 **ILSVRC 2012 우승** 모델로, 당시 ImageNet accuracy가 가장 좋았다.
- LeNet-5보다 복잡하지만 지금까지 배운 것으로 다 이해할 수 있다.
  - 입력: `227×227×3`
  - C1: kernel `11×11`, stride 4 → `⌊(227 + 0 − 11)/4⌋ + 1 = 55`, `55×55×96` (input channel 3 → output channel 96)
  - S2: max pooling kernel `3×3`, stride 2 → `⌊(55 − 3)/2⌋ + 1 = 27`, `27×27×96` (pooling은 장수 변화 없음)
  - C3: input channel 96 → output channel 256
- C1의 parameter 수: `(11×11×3 + 1) × 96` (= 34,944)
- 이렇게 끝까지 따라가서 첫 fully connected layer의 입력이 **`256×6×6`**이 되는 것을 계산할 줄 알아야 한다. Feature map 크기와 장수를 알아야 linear layer를 붙일 수 있다.
