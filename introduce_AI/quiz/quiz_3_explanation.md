## Q1. A\*, greedy best-first, weighted A\* (week2~3)

**정답:** (1) S(4) → A(4) → B(4) → C(4) → G(5), 갱신: C 4→3, G 7→5, 경로 S → B → C → G, 비용 5 (2) S → B → G, 경로 S → B → G, 비용 7 (3) S(8) → B(6) → C(5) → G(5), 경로 S → B → C → G, 비용 5 (4) A\* 5개, weighted A\* 4개

**(1) A\*** — $f(n) = g(n) + h(n)$

| 단계 | 꺼낸 노드   | 큐 (노드: g / f)                       |
|------|-------------|----------------------------------------|
| 1    | S (g0, f4)  | A: 1 / 4, B: 2 / 4                     |
| 2    | A (g1, f4)  | B: 2 / 4, C: 4 / 5, G: 7 / 7           |
| 3    | B (g2, f4)  | C: **3** / 4 (4→3), G: 7 / 7 (같음)    |
| 4    | C (g3, f4)  | G: **5** / 5 (7→5)                     |
| 5    | G (g5, f5)  | 목표를 꺼냈으므로 종료                 |

- 단계 2에서 A와 B의 $f$가 4로 같으므로 알파벳 순서로 A를 먼저 꺼낸다.
- B를 거치는 G 비용은 $2 + 5 = 7$로 기존 값과 같아 갱신되지 않는다.

**(2) Greedy best-first** — $f(n) = h(n)$
- 확장 순서와 꺼낼 때의 $f = h$: S(4) → B(2) → G(0)
  - S를 꺼내면 큐에 A: 3, B: 2 → B를 꺼내면 큐에 A: 3, C: 1, G: 0 → G를 꺼냄
- 경로 S → B → G, 비용 $g = 2 + 5 = 7$ ($f$ 값 4, 2, 0과는 별개)
- 최적 비용 5보다 비싸다. $g(n)$을 보지 않기 때문이다.

**(3) Weighted A\*** ($W = 2$) — $f(n) = g(n) + 2h(n)$
- S: $0 + 8 = 8$ → A: $1 + 6 = 7$, B: $2 + 4 = 6$ → B를 꺼냄
- B에서 C: $3 + 2 = 5$, G: $7 + 0 = 7$ → 큐 {A: 7, C: 5, G: 7} → C를 꺼냄
- C에서 G: $5 + 0 = 5$ (7→5) → G를 꺼냄. 경로 S → B → C → G, 비용 5

**(4)** A\*는 5개(S, A, B, C, G), weighted A\*는 4개(S, B, C, G)를 확장했다. 휴리스틱의 비중을 키우면 목표 방향으로 더 적극적으로 나아가 확장 수가 줄어든다. 이 그래프에서는 최적해도 찾았지만, 강의대로 weighted A\*는 최적성을 보장하지는 않는다.

## Q4. Threshold와 precision/recall (week6)

**정답:** (1) TP 3, FP 1, FN 1, TN 3 / precision 0.75, recall 0.75, accuracy 0.75 (2) TP 4, FP 3, FN 0, TN 1 / precision ≈ 0.571, recall 1.0, accuracy 0.625 (3) 0.3

- threshold 0.5: Positive 예측 = {0.9, 0.8, 0.7, 0.6} → 정답 1은 0.9, 0.8, 0.6 (TP 3), 0.7은 FP. 놓친 양성은 0.4 (FN 1)
- threshold 0.3: Positive 예측 = 0.35까지 7개 → 양성 4개 모두 잡음 (TP 4, FN 0), 음성 0.7, 0.45, 0.35가 FP 3
- precision $= 4/7 \approx 0.571$, accuracy $= (4 + 1)/8 = 0.625$

암 검진은 **FN(환자를 놓침)이 치명적**이므로 recall을 우선한다. threshold를 낮추면 recall이 오르고 precision은 떨어진다.

**함정:** accuracy만 보면 0.5가 더 좋아 보인다. 어떤 오류가 더 치명적인지에 따라 지표를 골라야 한다.

## Q5. Tautology 찾기 (week4)

**정답:** ① ② ⑤

| 보기 | 판단                                                                      |
|------|---------------------------------------------------------------------------|
| ①    | $\lnot P \lor Q \lor \lnot Q \lor P$ → 항상 참                            |
| ②    | 전제 $P \land Q$가 참이면 $P$가 참 → $P \lor \lnot Q$ 참                  |
| ③    | $P = T, Q = F$ → $T \to F$ = 거짓                                         |
| ④    | $P = F, Q = T$ → $T \to (T \to F)$ = 거짓                                 |
| ⑤    | Modus Ponens 그 자체 → 항상 참                                            |

①은 implication elimination으로 $(\lnot P \lor Q) \lor (\lnot Q \lor P)$가 되고, 안에 $Q \lor \lnot Q$가 들어 있다.

**함정:** ④는 "역(이, inverse)"이다. $P \to Q$와 $\lnot P \to \lnot Q$는 동치가 아니다.

## Q6. Viterbi — 새 확률값 (week5)

**정답:** (1) $P_1(T) = 0.27$ (T), $P_1(F) = 0.12$ (F) (2) $P_2(T) = 0.1458$ (T), $P_2(F) = 0.0324$ (T) (3) $P_3(T) = 0.008748$ (T), $P_3(F) = 0.040824$ (T) (4) (T, T, F)

- 관측 $U = F$일 때는 $P(U=F \mid T) = 0.1$, $P(U=F \mid F) = 0.7$을 쓴다.

**t = 1** ($U_1 = T$)
- $P_1(T) = \max(0.5 \cdot 0.6,\ 0.5 \cdot 0.2) \cdot 0.9 = 0.3 \cdot 0.9 = 0.27$ ← T
- $P_1(F) = \max(0.5 \cdot 0.4,\ 0.5 \cdot 0.8) \cdot 0.3 = 0.4 \cdot 0.3 = 0.12$ ← F

**t = 2** ($U_2 = T$)
- $P_2(T) = \max(0.27 \cdot 0.6,\ 0.12 \cdot 0.2) \cdot 0.9 = 0.162 \cdot 0.9 = 0.1458$ ← T
- $P_2(F) = \max(0.27 \cdot 0.4,\ 0.12 \cdot 0.8) \cdot 0.3 = \max(\mathbf{0.108},\ 0.096) \cdot 0.3 = 0.0324$ ← T

**t = 3** ($U_3 = F$)
- $P_3(T) = \max(0.1458 \cdot 0.6,\ 0.0324 \cdot 0.2) \cdot 0.1 = 0.08748 \cdot 0.1 = 0.008748$ ← T
- $P_3(F) = \max(0.1458 \cdot 0.4,\ 0.0324 \cdot 0.8) \cdot 0.7 = 0.05832 \cdot 0.7 = 0.040824$ ← T

**Backtracking:** $P_3(F)$가 큼 → $R_3 = F$ ← $R_2 = T$ ← $R_1 = T$ → **(T, T, F)**

**함정:** 전이 행렬이 대칭이 아니다. $P(F \mid T) = 0.4$와 $P(T \mid F) = 0.2$를 바꿔 쓰지 않도록 주의한다.

## Q9. 루트가 MIN인 alpha-beta (week3)

**정답:** (1) MAX 값 9, ≥10(실제 10), 8 / 루트 8, 오른쪽 자식 (2) 1 — 가운데 MAX에서 10을 본 직후 $\alpha = 10 \ge \beta = 9$ (3) 2(왼쪽 MAX의 마지막), 1 / 루트 값은 8로 같다

**(1)** MAX: $\max(3, 9, 2) = 9$, $\max(4, 10, 1) = 10$, $\max(8, 2, 5) = 8$ → 루트 MIN = 8

**(2) 왼쪽 → 오른쪽**
- 왼쪽 MAX: 3, 9, 2 모두 방문 → 9 → 루트 $\beta = 9$
- 가운데 MAX ($\beta = 9$): 4 → $\alpha = 4$, 10 → $\alpha = 10 \ge 9$ → **1 가지치기**
  - MIN은 이미 9를 확보했고, 이 MAX는 10 이상이므로 고를 이유가 없다.
- 오른쪽 MAX ($\beta = 9$): 8 → $\alpha = 8 < 9$, 2, 5 → 8 → 루트 $\beta = 8$

**(3) 오른쪽 → 왼쪽 → 가운데**
- 오른쪽 MAX: 8, 2, 5 → 8 → $\beta = 8$
- 왼쪽 MAX: 3, 9 → $\alpha = 9 \ge 8$ → **2 가지치기**
- 가운데 MAX: 4, 10 → $\alpha = 10 \ge 8$ → **1 가지치기**

**함정:** 루트가 MIN이면 루트가 $\beta$를 내리고, MAX 자식이 $\alpha$를 올리다가 $\alpha \ge \beta$에서 멈춘다. 방문 순서는 가지치기 수만 바꿀 뿐 루트 값은 바꾸지 않는다.

## Q15. bias로 NAND/NOR 만들기 (week6)

**정답:** (1) $1 \le b < 2$ (2) $0 \le b < 1$ (3) $b = 1$: NAND / $b = 2$: 모든 입력에서 1

$z = -x_1 - x_2 + b$

| 입력  | z      | NAND | NOR |
|-------|--------|------|-----|
| (0,0) | b      | 1    | 1   |
| (0,1) | b − 1  | 1    | 0   |
| (1,0) | b − 1  | 1    | 0   |
| (1,1) | b − 2  | 0    | 0   |

- NAND: $b \ge 0$, $b - 1 \ge 0$, $b - 2 < 0$ → $1 \le b < 2$
- NOR: $b \ge 0$, $b - 1 < 0$ → $0 \le b < 1$
- $b = 2$: (1,1)에서 $z = 0 \ge 0$ → 1. 모든 출력이 1이다.

**함정:** Heaviside는 $z = 0$일 때 **1**이다. 그래서 등호가 들어가는 쪽이 $b \ge 1$이고 $b < 2$이다.

## Q26. BFS와 DFS (week2)

**정답:** (a) `popleft` (b) `add` (c) `append` (d) `(['A', 'B', 'F'], ['A', 'B', 'C', 'F'])` (e) DFS, `(['A', 'C', 'D', 'E', 'F'], ['A', 'C', 'D', 'E', 'F'])` (f) BFS (d)

- BFS (FIFO): A → [B, C] → B 꺼내 F 추가 → C 꺼내 D 추가 → F 꺼냄
- DFS (LIFO): A → [B, C] → C(마지막에 넣은 것) → D → E → E에서 F 추가(아직 B가 확장되지 않아 F 미방문) → F
- 간선 비용이 같으면 BFS가 간선 수가 가장 적은 경로(2개)를 찾는다. DFS는 4개짜리 경로를 찾았다.

**함정:** `visited`를 꺼낼 때가 아니라 **넣을 때** 표시한다. 그래서 DFS에서 E가 F를 넣을 수 있었다.

## Q50. 학습 루프 순서 오류 (week7)

**정답:** (1) 파라미터가 전혀 갱신되지 않는다 (2) 아래 참고 (3) 아래 참고

- (1) `backward()`로 구한 gradient를 `zero_grad()`가 바로 0으로 지운 뒤 `step()`을 하므로, $W := W - \eta \cdot 0$이 되어 값이 그대로다. loss가 줄지 않는다.
- (2)

```python
for images, labels in train_loader:
    logits = model(images)               # forward
    loss = criterion(logits, labels)     # loss
    optimizer.zero_grad()                # 이전 gradient 초기화
    loss.backward()                      # backpropagation
    optimizer.step()                     # 파라미터 갱신
```

- (3) `model.eval()`: 모델을 평가 모드로 바꾼다. `torch.no_grad()`: 평가 때는 학습하지 않으므로 gradient 계산을 끈다.

**함정:** `zero_grad()`는 `backward()` **앞**이기만 하면 된다. 맨 앞(forward 전)에 둬도 같다.
