## Q1. `pip`가 없는 것 같은데 brew로 설치하면 되나?

**A.** brew로 설치할 필요는 없다. pip는 이미 설치되어 있고, `pip`라는 이름의 명령어만 없는 상태다.

- Homebrew Python 3.12에는 pip가 함께 들어 있지만, 명령어 이름이 `pip`가 아니라 **`pip3`** 또는 **`python3 -m pip`**이다.
- 다만 Homebrew Python에 바로 `pip3 install ...`을 하면 `externally-managed-environment` 에러가 날 수 있다(PEP 668: 시스템/brew가 관리하는 Python에는 직접 패키지를 설치하지 못하게 막는 정책).
- scikit-learn, datasets 같은 패키지는 brew로 설치하는 것이 아니라 pip로 설치하는 게 일반적이다.

**권장 방법: 가상환경(venv)을 만들어 그 안에 설치**

```bash
cd ~/dev/lecture/introduce_AI
python3 -m venv .venv                 # 가상환경 생성 (한 번만)
source .venv/bin/activate             # 가상환경 활성화 (터미널 열 때마다)
pip install pandas datasets scikit-learn matplotlib   # 활성화 후에는 pip 명령어 사용 가능
python week5/practice/iris_classification.py          # 실습 실행
deactivate                            # 가상환경 종료
```

- 가상환경을 활성화하면 그 안에서는 `pip`, `python` 명령어를 그대로 쓸 수 있다.
- 프로젝트별로 패키지를 따로 관리하므로 시스템 Python을 건드리지 않는다.
- VS Code에서는 인터프리터를 `.venv/bin/python`으로 선택하면 된다.
- `.venv` 폴더는 용량이 크므로 git에 올리지 않도록 `.gitignore`에 추가하는 것이 좋다.

## Q2. (HMM / Viterbi) 우산을 관측했으니까 P(Rₜ|Uₜ)를 써야 하는 거 아니야? 왜 식에는 P(Uₜ|Rₜ)가 들어가?

> 참고: 우산 예시는 단순 마르코프 체인이 아니라 **은닉 마르코프 모델(HMM)**이다. 마르코프 체인에는 관측(U)이 없고 상태(R)만 있다.

### 1) 직관은 맞다. 최종적으로 알고 싶은 건 "우산을 봤을 때 비가 왔나"다
- 목표는 P(비 | 우산) 방향, 즉 **관측 → 숨은 상태**를 추정하는 것이다.
- 다만 그걸 **직접 들고 다니지 않고, 베이즈 규칙으로 만들어 낸다.** 4주차 Q7과 같은 원리다.

  P(R | U) ∝ **P(R)** × **P(U | R)**
  (사전 확률 × 관측 모델)

### 2) Viterbi 식은 매 단계마다 이 베이즈 규칙을 적용한 것이다
**Pₜ(j) = maxᵢ [ Pₜ₋₁(i) · P(Rₜ=j | Rₜ₋₁=i) ] · P(Uₜ | Rₜ=j)**

| 부분 | 역할 | 베이즈 규칙에서 |
|---|---|---|
| maxᵢ [ Pₜ₋₁(i) · P(Rₜ=j \| Rₜ₋₁=i) ] | 어제까지의 정보 + 전이 모델 → "오늘 비가 올 것 같은 정도" | **P(R)** (사전) |
| P(Uₜ \| Rₜ=j) | 오늘 우산을 본 것이 그 상태와 얼마나 잘 맞나 | **P(U\|R)** (가능도) |

- 예 (t=1, U₁=T, 비가 온 경우):
  P₁(T) = max(0.5·0.7, 0.5·0.3) × **0.9** = 0.35 × 0.9 = 0.315
  - 0.35: 우산을 보기 전에 "오늘 비 왔을 것 같은 정도" (사전)
  - 0.9: "비가 왔다면 우산을 들고 올 확률" (관측 모델)
- 즉 P(Uₜ|Rₜ)를 곱하는 행위 자체가 **"우산을 관측했으니 그 증거로 R에 대한 믿음을 갱신한다"**는 뜻이다. 질문한 P(Rₜ|Uₜ) 방향으로 가는 계산이 바로 이것이다.

### 3) 그럼 왜 P(Rₜ|Uₜ)를 모델로 바로 주지 않나?
1. **P(U|R)은 원인 → 결과 방향이라 안정적이고 구하기 쉽다.**
   - "비 오는 날 우산 들고 올 확률 0.9"는 그 사람의 습관이라 어느 계절이든 거의 같다.
   - 반면 P(R|U)는 그 지역에 비가 얼마나 자주 오는지(사전 확률)에 따라 달라진다. 4주차의 P(뻣뻣한 목|수막염)과 같은 이유다.
2. **P(Rₜ|Uₜ)만 쓰면 어제 정보가 사라진다.**
   - "어제 비가 왔으면 오늘도 올 가능성이 높다"(전이 모델 0.7)는 정보를 쓸 수 없다.
   - P(R)×P(U|R) 형태여야 **과거(전이 모델)와 현재 관측(관측 모델)을 함께** 반영할 수 있다.

### 4) 분모 P(U)는 왜 없나?
- 베이즈 규칙의 분모 P(Uₜ)는 "비 옴(j=T)"과 "비 안 옴(j=F)" 후보에 **똑같이** 들어간다.
- Viterbi는 **어느 쪽이 더 큰지만 비교(max)**하면 되므로 분모는 생략한다.
- 그래서 표의 값들(예: 0.315와 0.07)은 더해도 1이 되지 않는다. 확률 자체가 아니라 **"이 상태로 끝나는 가장 좋은 경로 + 지금까지의 관측"의 결합 확률**이기 때문이다. 비교용 점수로 쓰는 것이다.

### 5) 한 줄 정리
- 알고 싶은 것은 P(R|U) 방향이 맞다. 하지만 계산은 베이즈 규칙대로 **P(R) × P(U|R)**로 한다.
- Viterbi 식의 앞부분이 P(R)(과거 + 전이), 뒷부분 P(Uₜ|Rₜ)가 관측 증거다. 분모는 비교에 필요 없어서 뺀다.

## Q3. (Viterbi) 그냥 식을 외워도 될까?

### 결론: 외워도 된다. 다만 "계산 순서 3단계"로 외우자
시험은 계산기를 허용하고, 힌트노트(A4 단면 1장, 수기)도 쓸 수 있다. 식을 **적어 가서 표를 채우는 것**이 핵심이다. 원리는 Q2 정도만 이해하면 충분하다.

**Pₜ(j) = maxᵢ [ Pₜ₋₁(i) · P(Rₜ=j | Rₜ₋₁=i) ] · P(Uₜ | Rₜ=j)**

외우는 방법 (오늘 상태 j 하나에 대해):
1. **어제 값 × 전이**: 어제의 각 상태 i에서 오늘 j로 오는 값 Pₜ₋₁(i)·P(j|i)를 구한다. → 2개
2. **max**: 둘 중 큰 것을 고른다. 이때 **어느 i에서 왔는지 메모**한다 (backtracking용).
3. **× 관측**: 오늘 관측 Uₜ에 맞는 P(Uₜ | j)를 곱한다.

→ 입으로 외울 때: **"어제 × 전이 → 최대 → × 관측"**

### 시험에서 자주 틀리는 포인트
- **max 위치**: 관측 확률을 곱하기 **전에** max를 한다. (관측 확률은 i와 무관하니 결과는 같지만, 순서를 지키면 덜 헷갈린다.)
- **관측 확률 고르기**: Uₜ=F(우산 없음)인 날은 P(U=F|R=T)=0.1, P(U=F|R=F)=0.8을 써야 한다. U=T 값을 그대로 쓰는 실수가 많다.
- **전이 확률 방향**: P(Rₜ=j | Rₜ₋₁=i)는 "어제 i → 오늘 j"다. 행렬로 주어지면 행 = 어제, 열 = 오늘인지 확인한다.
- **초기값**: P₀(T), P₀(F)가 문제에 주어진다 (강의 예시는 0.5, 0.5).
- **최종 답**: 마지막 날 더 큰 상태에서 시작한다. 메모해 둔 "어디서 왔는지"를 거꾸로 따라가면 전체 순서가 나온다 (강의 예시: T, T, F, T, T).
- **max ≠ 합**: Viterbi는 **max**다. 더하는 게 아니다. (모든 경로를 더하는 건 다른 알고리즘이다.)

### 힌트노트에 적을 것
- Viterbi 식 한 줄 + "어제 × 전이 → 최대 → × 관측"
- 빈 표 틀: t | 관측 | Pₜ(T) | Pₜ(F) | 어디서 왔나

## Q4. 기계학습에서 사람이 정형화된 데이터를 많이 모으기 힘들기 때문에 생긴 게 딥러닝인가?

### 1) 반은 맞다. 핵심은 "데이터 양"이 아니라 **"사람이 특징(feature)을 뽑기 힘들다"**는 점이다
- 기존 기계학습(결정 트리 등)은 **사람이 정해 준 feature**를 입력으로 받는다.
  - Iris: 꽃잎 길이, 꽃잎 너비 … → 사람이 이미 숫자로 재서 표(정형 데이터)로 만들어 줬다.
- 그런데 이미지·소리·텍스트 같은 **비정형 데이터**는 그대로는 표가 아니다.
  - 고양이 사진은 픽셀 수십만 개의 숫자일 뿐이다. 3주차 예시처럼 "삼각형 귀, 다리 4개, 털" 같은 feature를 **사람이 규칙으로 정의해서 뽑아내기가 매우 어렵다.**
  - 각도, 조명, 가려짐 등 모든 경우를 사람이 다 정할 수 없다. (5주차 "왜 ML이 필요한가"와 같은 이유)
- **딥러닝 = feature를 뽑는 과정까지 데이터로 학습하는 것.** 원본(픽셀)을 그대로 넣으면 여러 층을 거치며 유용한 표현을 스스로 만든다.
  - 6주차의 **임베딩 공간(latent space)**이 바로 이렇게 모델이 스스로 만든 "핵심 특징만 남긴 표현"이다.

| | 기존 기계학습 | 딥러닝 |
|---|---|---|
| feature | **사람이 설계** (feature engineering) | **모델이 학습** |
| 잘 맞는 데이터 | 정형 데이터 (표) | 비정형 데이터 (이미지·소리·텍스트) |
| 필요한 데이터 양 | 비교적 적어도 됨 | **매우 많이** 필요 |

### 2) 데이터는 오히려 "많이 모을 수 있게 돼서" 딥러닝이 가능해졌다
- 딥러닝은 데이터가 적어서 나온 게 아니라, **데이터가 많아져서 비로소 잘 작동하게 된** 방법이다.
- 1~2주차 AI 역사 흐름:
  1. 신경망 자체는 오래전부터 있었다 (퍼셉트론, 1987~ 역전파 재발견).
  2. **Big Data (2001~)**: 인터넷 덕분에 대규모 데이터셋(이미지·텍스트)을 모을 수 있게 됐다.
  3. **Deep Learning (2011~)**: 많은 데이터 + 계산 능력(GPU)이 갖춰지자 깊은 신경망이 실제로 성능을 내기 시작했다 (AlexNet 2012).
- 층이 깊을수록 파라미터(W, b)가 많다. 그래서 데이터가 적으면 **과대적합(overfitting)**되기 쉽다 (5주차).

### 3) 4주차 "추론 4갈래"와 연결
- 심층 신경망은 **"이미지, 소리 등 비정형 데이터에 대한 추론"**에 쓰인다고 했다. 바로 사람이 feature를 정하기 어려운 영역이기 때문이다.

### 4) 한 줄 정리
- 딥러닝이 나온 이유: 비정형 데이터에서 **사람이 feature를 직접 설계하기 어려워서**, feature까지 데이터로 학습하게 한 것이다.
- 데이터 양은 반대다. **많은 데이터(Big Data)가 있어야** 딥러닝이 잘 된다.

## Q5. 검증 집합(validation set)이 존재한다는 건, 훈련 단계에서 여러 가지 모델을 만든다는 뜻이야?

### 1) 맞다. 검증 집합은 **여러 후보 모델 중 하나를 고르기 위해** 있다
5주차 표의 역할 설명 그대로다: 검증 집합 = "모델을 평가해 **가장 좋은 모델을 고르는 데** 사용"

후보 모델은 보통 이렇게 만든다.
- **하이퍼파라미터를 바꿔서**: 결정 트리의 `max_depth`를 1, 2, 3, …, 10으로 바꿔 10개 학습
- **알고리즘을 바꿔서**: 결정 트리, 신경망 등 서로 다른 모델
- (참고) 신경망이라면 **학습 중간 시점별**로 저장한 모델들 (아래 3번)

### 2) 전체 흐름 예시 (결정 트리)
| 단계 | 사용하는 데이터 | 하는 일                                      |
| ---- | --------------- | -------------------------------------------- |
| 1    | 훈련 집합       | `max_depth` = 1~10으로 모델 10개를 각각 학습 |
| 2    | 검증 집합       | 10개 모델의 성능을 비교 → 가장 좋은 것 선택  |
| 3    | 테스트 집합     | 선택한 모델 1개를 **딱 한 번** 최종 평가     |

### 3) 왜 훈련 집합이나 테스트 집합으로 고르면 안 되나?
- **훈련 집합으로 고르면**: 복잡한 모델일수록 훈련 데이터를 외워서 점수가 높게 나온다. 결국 **과대적합된 모델**이 뽑힌다. (`max_depth`가 클수록 훈련 정확도는 계속 올라간다.)
- **테스트 집합으로 고르면**: 테스트 데이터에 가장 잘 맞는 모델을 고른 셈이다. 테스트 집합이 사실상 "본 데이터"가 되어 버린다. 그러면 최종 점수가 실제보다 **낙관적으로** 나오고, 진짜 처음 보는 데이터에서의 성능을 알 수 없게 된다.
- 그래서 역할을 나눈다: **훈련 = 학습, 검증 = 선택, 테스트 = 마지막 채점**

### 4) 연결: 6주차 K-Fold 교차 검증
- 데이터가 적으면 검증 집합을 따로 떼기 아깝다. 한 번 나눈 결과가 우연히 너무 좋거나 나쁠 수도 있다.
- 이때 K-Fold로 후보 모델마다 K번 평가한 **평균 성능**을 비교해서 고른다. 검증 집합의 역할을 더 안정적으로 하는 방법이다.

### 5) (참고, 강의 외) 신경망에서는 학습 도중에도 쓴다
- 학습을 반복할수록 훈련 손실은 계속 줄어든다. 그런데 어느 순간부터 **검증 손실이 다시 커지면** 과대적합이 시작된 것이다.
- 그 직전 시점의 모델을 고르는 방법을 **early stopping**이라고 한다. 이것도 "여러 시점의 모델 중 검증 성능이 가장 좋은 것을 고른다"는 같은 원리다.

### 6) 한 줄 정리
- 검증 집합이 있다 = 후보 모델이 여러 개다. 훈련 집합으로 각각 학습하고, 검증 집합으로 고르고, 테스트 집합으로 한 번만 최종 평가한다.

## Q6. 결정 트리가 잘 이해가 안 된다. 어떤 맥락에서 갑자기 나온 거야? 지도 학습의 일종인가?

### 1) 네, 지도 학습 모델이다
- 학습할 때 **정답(label)이 필요**하다. Iris라면 꽃 측정값(X)과 함께 종 이름(y)이 있어야 한다.
- **분류**(`DecisionTreeClassifier`)와 **회귀**(`DecisionTreeRegressor`)에 모두 쓸 수 있다.

### 2) 나온 맥락: "학습 → 테스트 → 평가" 흐름을 보여 줄 **예시 모델**로 등장했다
5주차 강의 순서를 보면 결정 트리는 갑자기 나온 게 아니라 **빈칸을 채우는 역할**이다.

| 순서 | 내용                               | 빈칸                          |
| ---- | ---------------------------------- | ----------------------------- |
| 1    | 지도 학습 정의: 입력 x → 출력 y    | 함수 h를 **무엇으로** 만들지? |
| 2    | 데이터: Iris, X/y 분리, train/test | 그림 속 "Model" 상자          |
| 3    | `model.fit()`, `model.predict()`   | `model = ???`                 |
| 4    | 성능 지표: 정확도, MAE, RMSE       | 무엇을 평가하지?              |
| 5    | **결정 트리**                      | 빈칸에 들어갈 첫 모델         |

- 슬라이드에도 "We will cover various learning methods to construct the model"이라고 쓰여 있다. "Model" 자리에 들어갈 **가장 단순하고 눈으로 보이는 예시**로 결정 트리를 고른 것이다.
- 바로 뒤에 ML 모델 목록(Decision tree, Random forest, XGBoost, SVM, KNN, …, Neural Network)이 나오고, "이 수업은 **신경망만** 깊게 다룬다"고 한다. 즉 결정 트리는 **본론(신경망) 전에 ML 흐름을 체험하는 예시**다.

### 3) 결정 트리가 하는 일: "스무고개"
질문(조건)을 차례로 던져서 답에 도달한다. 강의의 Iris 트리:
```
꽃잎 길이 ≤ 2.45?  ── 예 → setosa
        └ 아니오 → 꽃잎 너비 ≤ 1.65?  ── 예 → (꽃잎 길이로 한 번 더) versicolor / virginica
                                  └ 아니오 → virginica
```
- 4주차 **논리 규칙**(if 조건 → 결론)과 모양이 같다.
- 차이는 이것이다: 논리에서는 **사람이 규칙을 직접 썼다.** 결정 트리는 **어떤 feature를 어떤 기준값(threshold)으로 나눌지를 데이터에서 찾는다.**
  - 슬라이드: "without explicitly writing rules (which feature and threshold)"
  - 즉 "규칙을 사람이 쓰지 않고 데이터로 배운다"는 **기계학습의 핵심 아이디어를 가장 직관적으로 보여 주는 모델**이다.

### 4) "학습"이란 좋은 질문을 고르는 것: 불순도(impurity)
- 좋은 질문 = 나눈 뒤 각 그룹이 **한 클래스로 깨끗하게 모이는** 질문
- 섞여 있는 정도를 **불순도**라 하고, 대표 지표가 **Gini impurity**다.
  - (참고, 강의에 공식은 없음) Gini = 1 − Σ pₖ² (pₖ = 그 그룹에서 클래스 k의 비율)
- 6주차 예시 (Class1, Class2 개수):

| 노드         | 개수     | Gini  | 상태        |
| ------------ | -------- | ----- | ----------- |
| 시작         | (20, 20) | 0.5   | 최대로 섞임 |
| 규칙1 왼쪽   | (13, 0)  | 0     | 완전히 깨끗 |
| 규칙1 오른쪽 | (7, 20)  | 0.384 | 아직 섞임   |
| 규칙2 왼쪽   | (7, 4)   | 0.463 | 섞임        |
| 규칙2 오른쪽 | (0, 16)  | 0     | 완전히 깨끗 |

- **탐욕적(greedy)**: 매 단계에서 "지금 불순도를 가장 많이 줄이는 질문" 하나를 고르고, 아직 섞인 그룹에서 같은 일을 반복한다.
- `max_depth=3` = 질문을 최대 3단계까지만 한다. 너무 깊으면 훈련 데이터를 외워서 **과대적합**된다 (Q5의 검증 집합으로 적당한 깊이를 고른다).

### 5) 한 줄 정리
- 결정 트리 = **데이터로 if-then 규칙을 자동으로 찾는 지도 학습 모델**이다.
- 강의에서는 "fit → predict → 평가" 흐름을 보여 주는 첫 예시로 나왔고, 본론은 신경망이다.

## Q7. 그럼 데이터들이 결정 트리를 통해 어떤 클래스나 값에 도달하고, 그 정확도를 측정해서 모델을 평가하는 거야?

### 1) 맞다. 다만 **트리를 만드는 데이터**와 **평가하는 데이터**가 다르다
| 단계      | 데이터      | 하는 일                                           |
| --------- | ----------- | ------------------------------------------------- |
| `fit`     | 훈련 집합   | 질문(feature, 기준값)을 골라 트리를 **만든다**    |
| `predict` | 테스트 집합 | 만든 트리에 넣어 잎(leaf)까지 내려가 **예측한다** |
| 평가      | 테스트 집합 | 예측값 ŷ과 정답 y를 비교해 **점수를 낸다**        |

- 테스트 데이터는 트리를 만들 때 **한 번도 안 본** 데이터여야 한다. 그래야 "처음 보는 데이터에서도 잘하나"(일반화)를 잴 수 있다.
- 훈련 데이터로 평가하면 트리가 그 데이터에 맞춰 만들어졌으니 점수가 부풀려진다.

### 2) 잎(leaf)에 도달하면 무엇을 예측하나?
- 각 잎에는 **훈련 때 그 잎까지 내려온 훈련 샘플들**이 모여 있다. 예측값은 그 샘플들로 정한다.
  - **분류**: 그 잎에서 **가장 많은 클래스(majority class)** → 강의의 트리 시각화에 "Majority class"로 표시된 값
  - **회귀** (참고, 강의 외 보충): 그 잎에 모인 훈련 샘플 y값의 **평균**
- 예: 어떤 잎에 훈련 샘플이 versicolor 47개, virginica 1개 있다면, 테스트 꽃이 그 잎에 도착할 때 예측은 **versicolor**다.

### 3) 평가 지표는 문제 종류에 따라 다르다
| 문제 | 예측 결과 | 지표                                                       |
| ---- | --------- | ---------------------------------------------------------- |
| 분류 | 클래스    | 정확도(accuracy), 오류율, 혼동 행렬, 재현율·정밀도 (6주차) |
| 회귀 | 숫자 값   | MAE, MSE, RMSE                                             |

- 예 (분류): 테스트 꽃 30개를 트리에 넣어 28개를 맞혔다 → accuracy = 28/30 ≈ 0.93
- 코드로는 이 흐름이다:
  ```python
  model.fit(X_train, y_train)      # 훈련 집합으로 트리 만들기
  y_pred = model.predict(X_test)   # 테스트 데이터를 트리에 통과시켜 잎의 값 받기
  # y_pred와 y_test를 비교 → accuracy (분류) 또는 MAE/RMSE (회귀)
  ```

### 4) 한 줄 정리
- 훈련 데이터로 트리를 만들고, **테스트 데이터**를 트리에 통과시켜 잎의 값(다수 클래스 또는 평균)을 예측값으로 받는다. 그 예측을 정답과 비교해 정확도나 MAE/RMSE로 평가한다.
- 이 "fit → predict → 평가" 흐름은 결정 트리뿐 아니라 **신경망을 포함한 모든 지도 학습 모델에서 똑같다.**
